**仍未闭合（7）；已闭合：裸词 value 位非法（`each $f [in] xs`、`break done` 须改引号或 `$变量`；`<read> a.yml` 的裸词在宾语槽）。**
- **`//fn{` 词法与容器**：`//` 仍按行注释吃掉 `//fn{`，且 `header := "//fn" block` 的 `block` 只收 `statement*`，而 `statement` 已删 `fn_def`，定义无处安放。反例：`//fn{ @ "f" $x <read> $x { ... } }`。
- **`fn_template` 缺 `|>`**：产生式仍是 `[主语] <动词> 宾语 [(状语)] [[介宾]介宾宾语]`，示例的 `$path <read> $path |> <parse> yaml` 无法归约。反例：`@ "check-config" $path <read> $path |> <parse> yaml { ... }`。
- **TypeRegistry 与纯语法核心**：`typed_subject` 要靠宿主 TypeRegistry 判断 `file:` 是否类型前缀，核心只产 AST、不校验类型，无法在 Agent/Shell 两宿主下给出同一 AST 与合法性。反例：`file:/etc/passwd <read> ...` 在 Shell 合法、在 Agent 非法。
- **`expr` 无尾随块**：`expr := value | verb_call | pipe` 都不含 `trailing_block*`，与 §4.12「条件可带尾随块」冲突；若允许，条件块与 if body 无法切分。反例：`if <read> a.yml [error] { ... } { ... }`。
- **`[results]` 的块输出**：裁定只说 `[results]` 永远触发、数组长度=分支数，没说 parallel 块输出是 `[results]` 的 `$` 还是别的值。反例：`parallel { ... } [results] { ... } |> <write> out.yml`——`<write>` 收到数组还是块输出未定。
- **`//map` 单引号长词**：新规则让长词用单引号定义并展开为 value，§4.17 仍写「标记后到行尾是长词、按字面量、不转义、不解析」；含 `'` 的长词无法确定终止点。反例：`//map{ p'it's here }`——`'` 在 it 后终止还是到行尾。
- **`call_stmt` 参数位**：模板 `@ "check-config" $path <read> $path |> <parse> yaml` 中 `$path` 出现两次，按「`$变量` 出现顺序」是两位还是同名一位未写。反例：`@ "check-config" "a.yml"`——一个实参绑一个还是两个 `$path` 未定。
