# RILL v1.3 终审
- **`call_stmt` 与示例/绑定规则**：`call_stmt := "@" arg*` 只收实参，示例 `@ "prod" <read> "config.yml"` 里的 `<read>` 不是 `arg`；若照抄模板形状，又与「按位置绑定」和「签名匹配动词+状语+介词」两套规则并存冲突。反例：`@ "prod" <read> "config.yml"`——按 `arg*` 无法给 `<read>` 定槽。
- **`//fn{}` 与 `fn_def`**：定义搬入头部 `//fn{}` 后，`//fn` 无产生式，`statement` 仍含 `fn_def`，正文内联 `@ ... { ... }` 仍可解析；无 `//fn` 时调用 `@` 的报错阶段与错误串也未定义。反例：正文 `@ $x <read> $y { ... }`——按 `statement` 是定义，按「正文只调用」是调用。
- **`[results]` 的适用范围**：写入 §4.5 后它成了通用介词/尾随块，`branch := simple_stmt_with_trailing_blocks` 也未排除它，非 parallel 语句与 parallel 分支内都能写 `[results]`，而 `$` 语义只在 parallel 块级成立。反例：`parallel { <read> a.yml [results] { <send> $ [to] user } }`——分支内 `$` 指什么未定。
- **parallel 失败路径**：新产生式 `parallel_clause := "parallel" "{" branch* "}" ["[results]" block] [|> simple_stmt]` 删掉了 parallel 级 `[ok]/[error]`；分支 break 后 `[results]` 是否仍「全部完成后」触发、失败分支在数组里占不占位都未写。反例：`parallel { <read> a.yml <read> b.yml } [results] { <send> $ [to] user }`——a 失败时 `$` 是几元素数组未定。
- **Shell 类型前缀**：`file:/etc/passwd` 被定为「主语前缀」，但 §4.1 主语是角色，`类型:值` 未进 §三 主语产生式；裸词可含 `:`，解析器无法区分类型前缀与角色文本；`net:` 的值形态、Agent 宿主下该前缀是否合法也未写。反例：`file:/etc/passwd <read> ...`——主语是 `file:` + `/etc/passwd` 还是整个裸词，无规则。
- **N6 引号化与字面量**：§4.17 说长词按字面量处理、不转义，N6 却要求展示态按双引号规则转义；长词本身含 `"` 或 `\` 时，展示输出与压缩回读得到不同 token。反例：``//map{ p`a"b }`` 后引用 `` `p` ``，展示为 `"a\"b"`，再压缩已不是原长词。
- **`|>` 的 `{value, ok}`**：裁定只说动词返回二元组、`[ok]/[error]` 消费 ok，没说管道传 value 还是二元组；只传 value 则下游 `[error]` 失去 ok，传二元组则 `$` 与 if 的 truthy 又指什么。反例：`<read> missing.yml [error] { <send> "x" [to] user } |> <parse> yaml`——`<parse>` 收到 `"x"`、错误串还是二元组，未定。
- **顶层失败与 §4.10 冲突**：裁定 12 让顶层失败中断整个 program，§4.10 仍写「中断管道」；两条独立顶层语句时，前者说后续不执行，后者说不成管道故后续照跑。反例：`<read> missing.yml` 换行 `<send> "still runs" [to] user`——`<send>` 到底跑不跑。
- **`expr` 仍无 RHS**：`expr := simple_stmt_or_pipeline` 只是把未定义非终结符换名，`simple_stmt_or_pipeline` 没有产生式；`each [in]`、`break <值>`、`if <条件>` 的边界仍不能由文法唯一确定。反例：`break <read> a.yml |> <parse> yaml`——`|>` 属于 break 的 expr 还是 break 之后的管道，无规则。
- **each 每轮失败与 `[ok]` 的 `$`**：裁定 2 说每轮块输出作为一个元素，但只写了「分支」的 `[error]` 算成功/失败，没写每轮失败时循环是否继续、该轮占不占位，也没说 each 级 `[ok]` 的 `$` 就是该数组还是隐藏 do 的最后值。反例：`each $f [in] $files { <read> $f } [ok] { <send> $ [to] user }`——某一轮 `<read>` 失败时 `$` 是几元素数组、`[ok]` 是否触发均未定。
- **计数自相矛盾**：30 个唯一问题的构成里有「2 争议」，争议项按定义未闭合，与「全部闭合」冲突，且未给这两项编号。反例：`20 补文 + 6 规则 + 2 撤销 + 2 争议 = 30`——被计入的 2 项仍是争议。
