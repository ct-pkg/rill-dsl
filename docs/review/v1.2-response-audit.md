## 判错

- **R-15 撤销不成立**：`@ $s <read> $p [into]{...}{...}` 解析器能分清两个块，但 §三 `fn_template` 仍无 `trailing_block*`，`fn_def := "@" fn_template block` 只能吃一个 block；撤销理由只解决“谁是谁”，没解决“产生式没有入口”。
- **R-20 撤销不成立（即新⑤）**：``//map{ a`my application }`` 后展示 `my application`，长词含空格时“完整 token”不是单 token；要么把它定义成带引号的单个字符串 token（与 I-32 对齐），要么按词序列匹配，现有理由不足以撤销。
- **`[results]` 判错**：`parallel { <read> a.yml <read> b.yml } [results] { <send> $ } [ok] { <send> $ }` 中 `[results]` 不在 §2 符号总表、§4.5 常用介词表、§4.8 `$` 语境表；且“全部完成后触发一次”与“`[ok]/[error]` 逐分支触发”共存时，段输出取 `[results]` 的集合还是逐分支后的值，没有规则。
- **R-06 改 truthy 判错**：`<read> empty.yml [ok] { <send> "ok" } [error] { <send> "err" }`，成功返回 `""` 与失败返回空错误串都 falsy；同一 truthy 规则无法区分“成功但空”和“失败但空”，`[error]` 可能在成功时触发、在失败时漏触发。
- **I-37 与 I-49/R-17 判错**：`@ $s <do> $o { ... }` 与 `@ "engineer" <do> "x"`，I-37 保留“DSL 不做调用绑定”，I-49 又要求 `@` 调用按位置绑定；两条不能同时成立，除非把“工具调用”和“函数调用”拆成两套契约并改名。
- **第 9 条宿主无关判错**：`engineer <read> a.yml` 与 Shell 宿主的 `file:etc/passwd <read> a.yml`，§4.1 说主语＝内核角色＋权限，I-40 要求未知动词加载期报错；第 9 条说解析器不假设主语是角色、动词表由宿主注入，直接改写这两条，却没给宿主注入接口和错误阶段。
- **覆盖与计数判错**：33 行不是 33 个唯一问题——`I-04/R-04/R-24` 三合一，`R-28` 在 `I-37/R-28` 与 `I-39/R-28` 两行重复；回应自报 `23 补文＋10 已裁定＋2 撤销＋2 争议＝37`，若 2 撤销/2 争议属于 10 已裁定，应写成“10 中 2 撤销、2 争议”，否则有一号两判或重复计数。
- **R-04 部分闭合判错**：`each $f [in] $xs { <send> $f }` 中 `each_body := block`，回应只删 `expr`，`block` 仍无产生式；新增的 `prep_block_stmt` 也依赖 `block`，R-04 不能算全闭合。

## 会反弹

- **I-09 ↔ R-03/prep_block_stmt**：`<send> "x" [ok] user` 是介词短语，`[ok] user { ... }` 又可读成独立形式＋块；新增 `prep_block_stmt` 后，`]` 后是裸词还是 `{` 不能唯一决定归约。
- **R-09 ↔ R-12/I-18/R-13**：`each` 的 `[ok]/[error]` 里 `$` 说是“整个循环语句输出”，但 each 的输出（数组/最后值/聚合）没定义；parallel 又有 `[results]` 聚合，两个“循环/并行输出”规则会打架。
- **R-17 ↔ I-49/R-14/新④**：签名只匹配动词＋状语名＋介词名，主语/宾语参数化；I-49 又要求 `@` 调用按位置绑定，但槽位顺序、默认值跳位没给，匹配与绑定会各写一套。
- **I-32/C-7 ↔ R-20/R-19**：含空格长词“展开后整体是一个字符串 token”，展示态又要“展开映射表”；如果展示态不写引号，`my application` 是两个 token，回压时“完整 token”匹配不到长词。
- **R-21 ↔ R-20/R-22**：长词唯一按块检查，内外块可共用同一长词；反向映射 `configuration` 回内层 `k` 还是外层 `c` 没规则，按块唯一与全局可逆打架。
- **新① `[results]` ↔ 新②逐分支/R-13**：`[results]` 全部完成后一次，`[ok]/[error]` 逐分支；`$` 在 `[results]` 是集合，在 `[ok]/[error]` 是当前分支结果，段输出取谁没定义。
- **新⑧ each/parallel `|>` ↔ R-09**：`each` 可以接 `|>`，但 each 的输出值没定义（R-09 只说 `$` 是“整个循环语句输出”），管道下游拿不到确定值。
- **R-06 ↔ 新②逐分支**：truthy/falsy 逐分支触发时，成功返回 `0`/`""`/`[]` 的分支会走 falsy 支，失败返回空串的分支也会走 falsy 支；“逐分支各触发一次”无法区分。
- **R-12 ↔ 新① `[results]`**：分支内 `$`＝当前分支结果，块外＝汇总；`[results]` 也是汇总，`[results]` 的 `$` 与“块外汇总”是同一个还是两个，未定。
- **R-27 ↔ I-24/R-08**：顶层默认错误只中断当前语句；若当前语句在 `[ok]` 块内，`$` 是错误串、语句结果还是最近介词宾语，三条规则仍会给出不同答案。
