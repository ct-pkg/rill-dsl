# RILL v1.3 二次终审
闭合：1、2、3、4、5；value 无裸词维持非法（`each $f [in] xs`、`break done` 须改引号或 `$变量`，`<read> a.yml` 的裸词在宾语槽；属已定规则，示例需同步，不算未闭合）。
未闭合：
- 6：`//map` 的「标记符」未在 §二 定义，`p'a"b` 无法确定标记是反引号还是引号；且「回读为同一 value」不等于 AST 等价（长词节点与 STRING 节点）。反例：`//map{ p'some file }`。
- 7：`call_stmt := "@" STRING arg*` 的 `arg` 仍无产生式，无法判断它是否就是 `value`；`[into]` 的 `$变量` 按去重规则占位，`[ok]/[error]` 不在 `verb_call` 内故不占位。反例：`@ "check-config" "a.yml"`。
新问题：
- `expr` 的 `verb_call` 不再含主语，v1.2 条件 `if $cfg <contains> debug=true` 无法归约。反例：`if $cfg <contains> debug=true { ... }`。
- `//` 特例只写「`map`/`fn` 后接 `{`」，`//map {` 带空格时是否仍算 token 未定，词法可能按注释吞掉。反例：``//map { p`x }``。
