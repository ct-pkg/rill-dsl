# RILL v1.1 评审问题清单

> 口径：只以 v1.1 文本自身为准，不比较旧版设计；裸词默认按普通文本处理，不作为歧义来源；只考察 `<> () [] {} -> |> ` 引号、反引号等带标记成分之间的解析问题。每条给出最短反例、v1.1 依据、两席表态、档位与修补方向；档位分「确有问题 / 说的不够清晰 / 只需补例子」。本文件只记录问题，不改规范正文。

来源约定：`【反】` 表示反证席 24 条清单原条目；`【主】` 表示主张席独有、反证席未覆盖；`【合】` 表示两席指向同一处，合并为一条。

## 一、解析与词法边界

### I-01 扫描器把关键字语句读成主语
- **问题**：§六.2 的扫描器规定"非符号字符到主语（直到 `<`）"，`if/for/parallel/break` 都以关键字开头而非 `<`，按该算法会先被读成主语。
- **最短反例**：`if$cfg<contains>debug { <send> "on" [to] user }`
- **依据**：§六.2「非符号字符到主语（直到 <）」；§4.12–§4.15。
- **两席表态**：【主】主张席独有；反证席未直接提扫描器。
- **档位**：确有问题。
- **建议修补方向**：扫描器加"关键字优先"分支，并给出 `if/else/for/parallel/break` 关键字表。

### I-02 §三 的语句产生式覆盖不了四类语句
- **问题**：§三 只有 `[主语] <动词> 宾语 …` 一种形状，`if/for/parallel/break` 都不是它的实例。
- **最短反例**：`parallel { <read> a.yml <read> b.yml }`
- **依据**：§三 语句结构；§4.12–§4.15。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：增补 `statement := simple | if | for | parallel | break`，各给一行产生式。

### I-03 零空格态下 `else if` 无法书写
- **问题**：`else` 与 `if` 都是字母关键字，零空格规则下没有可用的分隔符，写成 `elseif` 又变成另一个词。
- **最短反例**：`if$cfg { <send> "a" [to] user } else if$cfg { <send> "b" [to] user }`
- **依据**：§4.18「传输/存储不含空格」；§4.12「支持 else if」。
- **两席表态**：【反 C21】一致。
- **档位**：确有问题。
- **建议修补方向**：允许相邻关键字之间保留一个空格，或给 `else if` 规定一个标记写法（如 `else:if`）。

### I-04 条件"任何表达式"没有表达式文法
- **问题**：§4.12 说条件可以是"任何表达式/复杂表达式"，但全文没有字面量、比较、算术、`and/or/not` 的产生式。
- **最短反例**：`if$cfg<contains>debug { <send> "on" [to] user }`
- **依据**：§4.12；§4.16 只定义引号；§二 未定义运算符。
- **两席表态**：【合】反证 C13，指向同一处；一致。
- **档位**：确有问题。
- **建议修补方向**：给最小表达式文法（字面量 + 比较 + `and/or/not`），或把条件限定为单个 `<动词>` 从句。

### I-05 `[in]` 在循环头与介词位同形
- **问题**：反证席认为 `[in]` 在同一行既是循环头标记又是介词，无法唯一解析。
- **最短反例**：`for$f[in]<search>*.yml { <replace> localhost [with] prod [in] $f }`
- **依据**：§4.13；§4.5。
- **两席表态**：【反 C8】反证提出但主张不同意：第一个 `[in]` 紧跟 `for$f`，第二个 `[in]` 跟在宾语 `prod` 之后，位置不同；只要 `for` 是关键字且有循环头产生式，读法唯一。缺的是关键字/产生式（I-01/I-02），不是 `[in]` 本身。
- **档位**：说的不够清晰。
- **建议修补方向**：补循环头产生式与 `[in]` 的两种位置说明，并给一行示例。

### I-06 `{}` 既是块又被列为 falsy 值
- **问题**：反证席认为 `{}` 同时是块和 falsy 字面量，`if$cfg{} { … }` 有两种读法。
- **最短反例**：`if$cfg{} { <send> "a" [to] user }`
- **依据**：§二；§4.12；§4.18。
- **两席表态**：【反 C10】反证提出但主张不同意：v1.1 没有对象字面量，`{}` 在这个位置只能是 `if` 的块；§4.12 的 `{}` 说的是运行期"空对象值"，不是字面量。按现有文字没有第二种解析。
- **档位**：说的不够清晰。
- **建议修补方向**：把 §4.12 的 `{}` 改写成"来自工具结果的空对象值"，避免与块标记同形。

### I-07 状语的"并列等价项"没有组合语义
- **问题**：`(utf-8,backup)` 是并列、顺序、去重还是数组，规范没有说，实际由底层库解释。
- **最短反例**：`<read> config.yml (utf-8,backup)`
- **依据**：§4.4「组合语义由底层库解释」。
- **两席表态**：【反 C12】一致。
- **档位**：说的不够清晰。
- **建议修补方向**：规定状语按顺序映射为具名参数或数组，并说明重复项的处理。

## 二、结构标记的角色冲突

### I-08 `[into]` 介词位与尾随位同形
- **问题**：`[into]` 既作介词带宾语，又作尾随块头，`[into] main { … }` 两种读法都合法。
- **最短反例**：`<merge> feature [into] main { <send> "done" [to] user }`
- **依据**：§4.5；§4.9（含 `[into]$cfg{...}`）。
- **两席表态**：【合】反证 C7；一致。
- **档位**：确有问题。
- **建议修补方向**：规定 `[into]` 后紧跟 `{` 时不得再带介词宾语；或改用独立块头 `into{...}`。

### I-09 `[ok]/[error]` 既在介词表里又是块头
- **问题**：`[ok]/[error]` 同时被列为常用介词和尾随块头，`[ok] user` 与 `[ok] { … }` 两种读法都成立。
- **最短反例**：`<send> "x" [ok] user`
- **依据**：§4.5「常用介词 … [ok] [error]」；§4.10「尾随区块」。
- **两席表态**：【合】反证 C9；一致。
- **档位**：确有问题。
- **建议修补方向**：从介词表删除二者，声明为保留块头；`[ok]` 后不跟 `{` 直接报错。

### I-10 尾随块挂在 `if/for/parallel` 上时触发面不明
- **问题**：`[ok]/[error]` 说"任何操作都可跟"，但挂在 `if/for/parallel` 上时，捕获的是条件求值、整个块还是块内第一条语句，没有规则。
- **最短反例**：`if$cfg { <send> "a" [to] user } [error] { <send> "b" [to] user }`
- **依据**：§4.10；§4.12；§4.13；§4.14。
- **两席表态**：【合】反证 C6 + 主张 U8；一致。
- **档位**：确有问题。
- **建议修补方向**：列出每种语句允许的尾随块及其捕获面（`for` 是否含 `[into]` 也一并写明）。

### I-11 `[into]` 与 `[in]` 的对照例子缺失
- **问题**：两处拼写本身可区分，但规范没有一行并列示例说明循环头的 `[in]` 与介词的 `[in]`、介词的 `[into]` 与块头的 `[into]`。
- **最短反例**：`for$f[in]<read> a.yml { <replace> localhost [with] prod [in] $f }`
- **依据**：§4.5；§4.9；§4.13。
- **两席表态**：【反 C23】一致。
- **档位**：只需补例子。
- **建议修补方向**：补两行对照示例，标出每处 `[in]/[into]` 的角色。

## 三、错误与控制流

### I-12 不写 `[error]` 时"错误被忽略"没有后状态
- **问题**：错误被忽略后，本段输出是什么、`[ok]` 是否触发、后续语句是否继续，都没有定义。
- **最短反例**：`for$f[in]<read> empty.yml { <send> $f [to] user }`
- **依据**：§4.10「不写 [error] 时错误被忽略」；§4.13「不写则忽略（执行零次）」。
- **两席表态**：【合】反证 C1；一致。
- **档位**：确有问题。
- **建议修补方向**：默认改为错误向上抛；要吞掉必须显式写空 `[error]{}`，并说明输出为 null、`[ok]` 不触发。

### I-13 `for` 的 null 从句双重归类
- **问题**：null 同时命中"非数组→单元素数组（执行一次）"和"null→error（不写则零次）"两条规则。
- **最短反例**：`for$f[in]$missing { <read> $f }`
- **依据**：§4.13 原文两句。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：判定顺序改为"null 先判 error；其余非数组才单元素化"。

### I-14 多个 `[into]` 与 `[error]` 的失败中断顺序未定义
- **问题**：`[into]` 说按书写顺序逐个执行，`[error]` 说最后执行；若第一个 `[into]` 失败，后续 `[into]` 是否执行、`[error]` 是否还"最后"没有规则。
- **最短反例**：`<read> a.yml [into] { $ <replace> [with] 1 } [into] { $ <replace> [with] 2 } [error] { <send> "fail" [to] user }`
- **依据**：§4.11；§4.10。
- **两席表态**：【反 C4】一致（主张席补充：这是失败中断规则缺失，不只是顺序措辞）。
- **档位**：确有问题。
- **建议修补方向**：规定 `[into]` 失败即中止本段并跳到 `[error]`，后续 `[into]` 不执行。

### I-15 `break` 出现在 `[ok]/[error]` 里时场域不明
- **问题**：§4.15 说"不存在无场域的 break"，但示例1 在 `[error]` 里写 `break`；反证席认为它与管道输出冲突。
- **最短反例**：`<read> a.yml [error] { <send> "fail" [to] user break } |> <write> b.yml`
- **依据**：§4.15；§4.6；§五示例1。
- **两席表态**：【合】反证 C2；反证提出，主张部分同意：场域可以读作外围管道段，所以不是"无场域"矛盾；真正缺的是 break 之后管道是否继续、输出给谁。
- **档位**：确有问题。
- **建议修补方向**：规定块内 `break` 继承最近的管道段/`for` 体，并明确中断后无输出、下游不执行。

### I-16 `break <值>` 没有捕捉语法
- **问题**：`break` 说"值传给管道外部，由外部变量捕捉"，但全文没有捕捉语法。
- **最短反例**：`<read> a.yml |> <write> b.yml [ok] { break 3 }`
- **依据**：§4.15；§三 只有语句末尾 `->$变量`。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：定义 `break <值> ->$var`，或删除带值 break。

### I-17 `[error]` 的错误对象没有字段表
- **问题**：§4.8 说 `[error]` 里 `$` 是"错误对象/信息"，但没有说明可读哪些字段。
- **最短反例**：`<read> a.yml [error] { <send> $.kind [to] user }`
- **依据**：§4.8；§4.10。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：定义 `kind/message/line` 三个只读字段，或明确 `$` 只是消息字符串。

### I-18 `parallel` 没有汇合与失败语义
- **问题**：块本身不说明产出什么，`|>` 无法接；某一分支失败时 `[error]` 看到什么、块是否整体失败，也没有规则。
- **最短反例**：`parallel { <read> a.yml <read> b.yml } [ok] { <send> "done" [to] user }`
- **依据**：§4.14 全节；§4.6。
- **两席表态**：【合】反证 C16；一致。
- **档位**：确有问题。
- **建议修补方向**：规定块输出（按源序的结果数组）与失败策略；做不到就把 `parallel` 移出 v1.1。

## 四、作用域与变量

### I-19 `->$x` 同时是声明和赋值，与"禁止重名"互斥
- **问题**：`->$x` 既可首次声明又可再次赋值，而 §4.7 又说同一作用域链不允许重名；循环每轮、兄弟块、parallel 分支的 scope 身份也没有定义。
- **最短反例**：`<read> a.yml->$x` 后接 `<read> b.yml->$x`
- **依据**：§4.7；§4.8；§4.14。
- **两席表态**：【合】反证 C3+C18；一致。
- **档位**：确有问题。
- **建议修补方向**：拆成 `->$x`（首次声明）与 `$x ->`/`$x =`（再赋值）；规定每轮循环、每个分支是新作用域。

### I-20 `parallel` 分支写同一外部变量没有冲突规则
- **问题**：§4.14 允许块内使用外部变量，§4.7 又允许变量重新赋值；两个分支同时写同一变量时，结果不确定。
- **最短反例**：`parallel { <read> a.yml->$x <read> b.yml->$x }`
- **依据**：§4.14；§4.7。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：禁止分支写外部变量，或规定快照 + 写冲突报错。

### I-21 `[into]` 的重名禁令在尾随形式里没有指代对象
- **问题**：§4.9 说"[into] 块内禁止声明与进入 into 的那个变量同名的变量"，但尾随形式 `[into] { … }` 没有"变量"。
- **最短反例**：`<read> a.yml [into] { <read> b.yml->$cfg }`
- **依据**：§4.9；§4.7。
- **两席表态**：【主】主张席独有。
- **档位**：说的不够清晰。
- **建议修补方向**：把该禁令限定到 `[into]$cfg{...}` 形式；尾随形式删掉这句。

### I-22 `if` 不是表达式、`->$x` 只能声明，分支无法产值
- **问题**：§4.12 说 `if` 不参与管道、只能是独立语句，§4.7 的 `->$x` 又是声明；两边分支无法把值传给后续。
- **最短反例**：`if$cfg<contains>debug { <read> a.yml->$x } else { <read> b.yml->$x }`
- **依据**：§4.12；§4.7。
- **两席表态**：【主】主张席独有。
- **档位**：说的不够清晰。
- **建议修补方向**：说明分支产值靠修改外层变量或 `$`，并给一行示例；或让 `if` 成为表达式。

## 五、`$` 语义

### I-23 `$` 既是固定 self 又是变量前缀
- **问题**：反证席认为 `$` 同时是 self 和 `$var` 的变量前缀，无法区分。
- **最短反例**：
```rill
<read> a.yml->$c
<read> $c
```
- **依据**：§4.7；§4.8。
- **两席表态**：【合】反证 C5 + 主张 U1；反证提出但主张不同意：`$c` 是 `->$c` 绑定的变量，`$` 单独出现才是 self；self 的字段在 §4.9 写作 `.host`，全文没有 `$.host`，所以按现有文字没有第二种读法。
- **档位**：说的不够清晰。
- **建议修补方向**：补一句"`$name` 是变量，`$` 是当前 self，`.name` 是 self 字段"。

### I-24 `$` 的四种指代在嵌套时没有优先级
- **问题**：`$` 在 `[into]/for/[ok]/[error]` 各有指代，但互相嵌套时（如 `[ok]` 内嵌 `[into]`、`[error]` 内嵌 `for`）没有规则。
- **最短反例**：`for$f[in]<search>*.yml { <read> $f [into] { $ <replace> [with] 1 } [ok] { <send> $ [to] user } }`
- **依据**：§4.8；§4.10。
- **两席表态**：【合】反证 C15；一致。
- **档位**：确有问题。
- **建议修补方向**：规定"最近包围块优先"，并给 `[ok]` 内嵌 `[into]` 的一条规则。

### I-25 `[into]` 示例假设 `<read>` 返回已解析对象
- **问题**：示例直接对 `<read>` 的结果写 `.database`，但规范没有说 read 会解析文件内容。
- **最短反例**：`<read> /app/config.yml [into] { .database <replace> [with] prod-db:5432 }`
- **依据**：§4.9 示例；§4.5。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：规定 read 返回 string，进入 into 前必须显式 `<parse>`；或把示例写成 parse 后的对象。

## 六、管道与尾随区块

### I-26 `|>` "只能在行尾"与所有示例冲突
- **问题**：§4.6 说 `|>` 只能出现在行尾，但示例1/2 都写成 `... |> <write> ...`，同一行还有下一段。
- **最短反例**：`<read> a.yml |> <write> b.yml`
- **依据**：§4.6；§五示例1/2。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：改成"`|>` 后接下一段；可同行，跨行时留在物理行尾"。

### I-27 `[ok]/[error]` 的"最后执行"与管道取输出冲突
- **问题**：§4.11 说 `[ok]/[error]` 最后执行，§4.6 又说管道取"含尾随区块处理后的输出"；两者对同一段代码给出不同顺序，且尾随块后的默认输出没有定义。
- **最短反例**：`<read> missing.yml [error] { <send> "fail" [to] user } |> <write> b.yml`
- **依据**：§4.11；§4.6；§4.10。
- **两席表态**：【合】反证 C14；一致。
- **档位**：确有问题。
- **建议修补方向**：明确顺序 `into → ok/error → 段输出 → |> 下游`，并规定 `[error]` 执行后的默认输出。

### I-28 尾随块覆盖"本段"还是"整条管道"不明
- **问题**：示例2 每段各写一个 `[error]`，暗示按段；§4.6 又说管道取"整条语句"的输出，暗示按整条管道。
- **最短反例**：`<read> a.yml [error] { <send> "read fail" [to] user } |> <replace> localhost [with] prod [error] { <send> "replace fail" [to] user } |> <write> a.yml`
- **依据**：§4.6；§五示例2。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：定义"管道段"：`|>` 分隔段，尾随块只覆盖本段，`[error]` 不跨 `|>`。

### I-29 尾随块数量在 §三 / §4.10 / §4.11 之间不一致
- **问题**：§三 只有一个 `[尾随区块]` 槽，§4.11 说 `[ok]/[error]/[into]` 可以叠加，§4.10 又说 `[ok]/[error]` 各至多一个。
- **最短反例**：`<read> a.yml [into] { $ <replace> [with] 1 } [into] { $ <replace> [with] 2 }`
- **依据**：§三；§4.10；§4.11。
- **两席表态**：【主】主张席独有。
- **档位**：确有问题。
- **建议修补方向**：§三 写成 `trailing_block*`，并给每类次数上限（`[into]` 多个，`[ok]/[error]` 各 0..1）。

### I-30 `[ok]` 自己的输出通道没写

- **最短反例**：`<read> a.yml [ok] { <send> "done" [to] user }`

## 七、`//map`

- **问题**：§4.17 说只有反引号包裹的短词才查表，又说 `<read>` 可以压成 `<r>`；后者没有反引号。

## 必须闭合的五条

1. **关键字、语句产生式与扫描器**（I-01/I-02/I-03）：没有它，`if/for/parallel/break` 连解析都过不去。
2. **调用绑定与管道值落槽**（I-37/I-38）：没有它，工具调用无法落到 `args_json`，arity 也无法校验。
3. **尾随块的顺序、覆盖范围与默认输出**（I-10/I-26/I-27/I-28/I-29/I-30）：没有它，同一段代码的执行顺序与输出都有多种读法。
4. **错误模型**（I-12/I-13/I-14/I-15/I-16/I-17）：包括默认传播、`[error]` 对象字段、break 与失败中断。
5. **作用域与 `->$x`**（I-19/I-20/I-21/I-22）：声明/赋值不拆开，"同一链不重名"无法静态判定，循环与并行也无法实现。

## 两席分歧

- **I-05（反证 C8）`[in]` 双角色**：反证席认为无法唯一解析；主张席认为循环头与介词位的位置不同，只要 `for` 是关键字且有循环头产生式就能唯一解析，缺的是 I-01/I-02 的产生式，不是 `[in]` 本身。
- **I-06（反证 C10）`{}` 块/falsy**：反证席认为有两种读法；主张席认为 v1.1 没有对象字面量，该位置只能是块，§4.12 说的是运行期空对象值，属于措辞问题。
- **I-15（反证 C2）`break` 与管道**：反证席认为 §4.6 与 §4.15 冲突；主张席认为场域可读作外围管道段，不是"无场域"矛盾，真正的缺口是中断后的输出规则。
- **I-23（反证 C5）`$` 双身份**：反证席认为 self 与变量前缀无法区分；主张席认为 `$c` 是变量、`$` 单独才是 self、字段写作 `.host`，按现有文字解释得通，只需补一句定义。
- **I-39（反证 C11）逗号与数组**：反证席判为语义空洞；主张席认为 §4.3 的"DSL 不判断"本身是明确规则，问题在结果——没有数组实参表示，属于能力缺口而非解析歧义。
