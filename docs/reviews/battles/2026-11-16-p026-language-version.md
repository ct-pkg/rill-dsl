## 2. 三席（立场独立，不互相让步）

### 2.1 主张席：选 `0.2.0`

1. **这是世代变更，不是修订。** D-022 删除 `@ "name"` 后，任何含函数的脚本都必须改写定义与调用两处形态。补丁号在语义上等价于「无需行动」，与事实相反。
2. **只有 `0.2.0` 能让 `dsl-version` 诚实。** `1` 原本指「允许 `@ "name"` 的 0.1 文法」。D-022 后引擎拒绝它。若版本仍记 `0.1.2` 且头仍写 `1`，同一个 `1` 就同时指代两套不兼容文法——header 变成谎报，将来任何工具都无法靠它判断脚本属于哪一代。
3. **失败点必须前移到加载期。** 旧脚本的失败目前只在解析到函数时才由 `E-07` 触发；若声明 `dsl-version:1` 在加载期直接 `E_VERSION`，失败发生在「任何工具都不执行」之前（[S-021 §3](../../spec/S-021-dsl-version.md#L24-L32)）。这是比解析期更早、更安全的栅栏位置。补丁号不会带来这个效果。
4. **0.x 的 minor 正是装破坏性变更的。** SemVer 对 `0.y.z` 写明「anything MAY change」，把破坏性变更放进 minor 是 0.x 的常规做法，不构成 1.0 承诺，也不构成「已发布」。
5. **1.0 路径。** 现在建立「minor = 文法世代」这一不变式，1.0 时冻结世代即可；若破坏全部埋在 patch 里，1.0 会变成一次无预告的悬崖。

主张席要求的最小判据：H1 = `0.2.0`；`dsl-version` 常量 = `2`；`1` 在加载期报 `E_VERSION`；旧语料 `E-07`；产品版本不动。

### 2.2 反证席：选 `0.1.2`

1. **未发布，无兼容承诺。** 语言规范没有任何发布 tag，外部零用户；唯一 tag 是产品 `v0.22.0`，与语言版无关。0.x 阶段没有需要「守信」的对象。
2. **`0.2.0` 会制造「已发布感」。** 外部读者会把 0.2.0 读成第二个公开版本，而实际没有任何发布动作；它会连带引出「0.2 要不要 tag、要不要迁移指南、要不要对外公告」的连锁问题。
3. **会复杂化 `dsl-version`。** 若选 `0.2.0` + `2`，必须先回答「`1` 算什么」：保留 legacy parser 违反 D-022「不保留回退路径」；把 `1` 判死，则是给一个**从未实现过**的 header 新增「已退役世代」语义。`0.1.2` 只需维持「只有一套文法，头就写 1」，与 D-018「不引入第二套文法」「不得提前分派」完全一致。
4. **「栅栏」论点不成立。** 旧语料不会静默错解：`@ "name"` 一定 `E-07`，位置在字符串 token，带迁移 Hint。`E-07` 已经是栅栏；版本号加不加 minor 不改变任何加载或执行行为。主张席把**标签**当成了**闸门**。
5. **有先例。** `0.1.1` 的 B1 同样是破坏性的，当时按 patch 记。D-022 范围更大，但政策应先保持一致，除非同时推翻 0.1.1 的记法。
6. **成本最低。** 不改 `dsl-version`、不动旧 10 卷「不升版本号」条款、不新增世代语义；只改 H1 与修订记录一行。

### 2.3 成本席：逐项算账

| 成本项 | 选 `0.2.0` | 选 `0.1.2` | 差额 |
| --- | --- | --- | --- |
| 已有语料（examples/testdata/测试夹具） | 0 处旧形态；85 个 fixture 不用改；迁移成本已在 PH-22-T6 付清 | 同左 | **0** |

| `dsl-version` 校验 | 需把 `version_line` 写回 RILL §三（现在没有）；常量 `2`；`1`→`E_VERSION`+迁移 Hint；`3`→`E_VERSION`；`1.0`/`v2`→`syntax`；重复→`dup_header`。约 S 级，但新增「退役世代」语义 | 常量 `1`，与 D-018 原文一致，最小实现 | 0.2.0 多约 1 个任务、多一层语义 |

## 4. 裁定建议（签字版）

### 4.1 选号：`0.2.0`（`0.1.1 → 0.2.0`）

理由按优先级：

1. **世代变更**：所有含函数的脚本都要改写，这是文法世代变化，不是文档修订。
2. **header 诚实**：只有 `0.2.x ↔ dsl-version 2` 能保证「声明的版本 = 引擎接受的文法」。
3. **失败前移**：`dsl-version:1` 在加载期失败，早于任何工具执行；比只靠解析期 `E-07` 更安全。
4. **1.0 路径**：现在确立「minor = 世代」，1.0 才有可冻结的边界。

明确**不采纳**主张席的「否则会静默错解」作为核心理由（该理由经核实不成立）；也不采纳反证席的「未发布所以只能 patch」（0.x 的 minor 不承诺 1.0，未发布不等于不能标世代）。反证席的「`1` 的语义」问题由 4.2 直接回答，不再悬空。

### 4.2 `dsl-version` 允许值

确立不变式：**`dsl-version` 的整数 = 规范 MINOR**（`0.2.x → 2`）。

| 输入 | 行为 |
| --- | --- |
| `# dsl-version: 2` | 接受，不改变解析 |
| 省略 | 按 `2` 解析（header 仍可选） |
| `# dsl-version: 1` | **加载期** `E_VERSION`，Hint：0.1 的函数名语法已退役，删除 `@ "name"` 的字符串名，按形状调用；本引擎只接受 `2` |
| `3` 或其他整数 | 加载期 `E_VERSION`，Hint：`only '# dsl-version: 2' is supported` |
| `1.0` / `2.0` / `v2` | `syntax`（只收裸整数） |
| 重复版本头 | `dup_header` |

同时明确：**不实现 legacy parser，不启用 D-018 的「按版本分派」。** 这是对 D-018 失效条件的有意收窄——现在只有一套可加载文法，`1` 直接判死，而不是分派到旧解析器。该收窄需在新决策记录（建议 `D-023`）中写明，不能默默改 D-018。

代价声明：需把 `version_line` 重新写回 RILL §三（当前 `header` 只含 `//map`/`//fn`），并更新 S-021；在实现落地前，`E-07` 仍是唯一的运行期栅栏。

### 4.3 旧 `@ "name"` 语料：**报错，不迁移、不做兼容层**

- 引擎契约：解析期 `E-07`；若脚本声明 `dsl-version:1`，更早的加载期 `E_VERSION`。两者都给迁移 Hint。
- 迁移由作者或工具完成，规则固定：删掉 `@` 后的字符串名；常量主语写裸词/引号，参数主语写 `$变量`；调用按模板每个参数位写值；同形冲突先合并或调整形状。
- 仓库现状：可执行旧形态为 **0**，无需批量迁移。仅需把 [RILL §九 L762](../../RILL-0.1.0.md#L762) 改为「`0.1.1` 曾合法，自 `0.2.0` 起 `E-07`」，消除与 §4.18 的矛盾。
