## 3. 构建必须分两次 `ct build`（本相撞到的新阻塞）

### 3.1 现象

把 Agent 宿主按多单元落进 `ct/src/host/agent*.h.ct` 后，整个 `ct build` 报：

```
src/host/agent_caps.h.ct:36:63: error: too many calls
```

### 3.2 实测：预算不是「每单元 256 函数」，是「每次 build 全局 1024 个已解析调用点」

`ct v0.49.0` 的 `MAX_CALLS` 定义在 `selfhost/ct-ast/frontend/parse/Expr.h.ct:55`，
由 `record_call()`（同文件 6059）在**调用点解析到已知函数**时累加，跨单元不重置。
三个探针（`/tmp/ph20/p1..p3`）：

| 探针 | 内容 | 结果 |
| --- | --- | --- |
| p1 | 单文件 1100 次 `g(...)` | `m.ct:1027:11: error: too many calls`（第 1025 个调用点） |
| p2 | 两个单元各 600 次跨单元 `g(...)` | `b.ct:427:10: error: too many calls`（600+424=1024） |
| p3 | 先 `static` 前置声明、1100 次调用、再定义 | 仍在 `1027` 失败（**声明也算解析**） |

结论：预算按整个 build 的已解析调用点累计；`static` 包装函数不能省（包装体自身
仍是一个调用点，调用方也仍是一个）。把热路径收成单字母包装（PH-20 早期的
`sj/oj/pj/...`）实测无效，已在本次改动里全部删除。

### 3.3 量化：PH-19 基线已经用掉 927/1024

在 PH-19 基线上追加一个只含 N 次 `jint()` 调用的探针单元（`import` 在最后）：

```
N=95 PASS    N=100 FAIL（src/main.ct:36:43: error: too many calls）
```

即 PH-19 收口时已用掉 **927** 个槽位，只剩约 97；Agent 宿主实测需要约 500。
继续改写源码压到 97 以内不现实（等价于把 Agent 能力砍掉五分之四），所以改构建。

### 3.4 处置：语言核心出静态库，宿主层消费

`ct build --lib` 允许把一组单元编成 `.a`，并把导出类型的头文件留在 `--outdir`；
另一次 `ct build` 可以 `#include` 这些生成头、用 `--ldflags` 链上去（探针
`/tmp/ph20/p4`、`p7`：`#include` 会原样进生成头；`-fvisibility=hidden` 的静态库
成员仍能被静态链接解析）。据此把构建切成两段：

| 层 | 单元 | 产物 |
| --- | --- | --- |
| 一（语言核心） | `common` `lexer` `parser` `loader` `formatter` | `ct/build/librill_core.a` + `ct/build/gen-lib/*.h` |
| 二（宿主与入口） | `eval` `json` `exec` `host` `shell` `agent*` `cli` `main` | `ct/bin/rill_ct` |

边界上只有三处需要人工对齐（都写在 `ct/src/host/bridge.h` 与 `ct/build.sh`）：

1. **类型拼写**：生成头把导出类型写成 `struct JVal`，宿主层单元不再 `import`
   `common`，ct 也不认识 `JVal` 是结构体，只会原样搬。`bridge.h` 补齐
   `typedef struct JVal JVal;` 等 14 个别名。
2. **`pub` 全局量**：`ct build --lib` 拒绝导出 `pub` 全局量
   （`Module.h.ct:1138`），`common` 的 `g_diag` / `g_fail_jmp` 收成 `static`，
   `main` 改用 `fail_jmp_slot()` 取地址（`setjmp` 仍在 `main` 帧）。
3. **trait 方法**：宿主层不认识 `Emitter`，`out.emit()` 会落到未初始化的
   `__emitter_vptr`（实测段错误 rc=139）。输出逻辑移进自由函数
   `emitter_emit()`，trait 方法只做转发。

### 3.5 代价

- `ct/build.sh` 从一条命令变成两条，多一个 `ct/build/gen-lib/` 中间目录
  （已加进 `.gitignore` 之外的手工清理，每次 build 先 `rm -rf`）。
- 跨层调用不再有 ct 的元数/类型检查，靠 `bridge.h` 的 typedef 与 `cc` 兜底；
  代价是边界写错时报的是 `cc` 错误而不是 ct 诊断。
- 不引入宏、不引入单字母包装、不改 lexer/parser，调用点总量不变 —— 只是分成两次
  编，各自都在 1024 以内。

## 5. 定向用例：`real-transport`

`real-transport.rill` 用 `profiles/tools.json` 里的真实子进程工具
（`python3 tools/tool_server.py`，JSON stdin/stdout），不是队列桩；两侧都比
`ok/value/host_meta`。

唯一不可比字段是 `host_meta.tool_meta.transport.pid` —— 两侧是不同进程，进程号
必然不同。按 AST `span` 的同类处理：**从等值比较中剔除，但保留在输出里**
（`diff.py: strip_pid()`）。剔除后 `directed=1 directed_diffs=0`。
