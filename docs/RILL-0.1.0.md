## 一、概述

RILL 是一门专为 AI Agent 设计的领域特定语言（DSL）。它采用 SVO 语序，由 LLM 生成指令，由引擎解析执行，底层调用系统工具完成实际操作。

定位：

- 首要目的：Agent 与 LLM 之间的通信协议——LLM 生成，引擎执行。
- 次要目的：让没有编程训练的人能轻松读懂脚本语义。
- 压缩是手段，不是目的本身：零空格、符号边界、映射表共同服务“传输紧凑 + 人类可读”。

核心设计理念：

- 零冗余：传输/存储时不含空格，每个字符都有语义。
- 符号即边界：`<> () [] -> {} $ |> @` 等符号充当成分分隔符，有符号在，空格可去。
- 一句一动词：一个语句只能有一个动词，多个动词必须拆成管道。
- LLM 友好：语法规则极少，SVO 语序符合自然语言习惯，祈使句无主语。
- 双层表示：压缩态（传输/存储）与展示态（人类阅读）分离，双向可逆。
- 管道 + 尾随区块是重心：良好脚本以链式结构为主，变量和独立语句是少数。

| --- | --- | --- | --- |

## 三、语句产生式

```ebnf
program        := header* statement*

header         := map_block | fn_block
map_block      := "//map" "{" map_entry* "}"
fn_block       := "//fn"  "{" fn_def* "}"
map_entry      := 短词 标记符 长词

statement      := simple_stmt | prep_block_stmt | if_clause | each_clause
                | parallel_clause | break_stmt | call_stmt

simple_stmt    := verb_call trailing_block* [ "|>" simple_stmt ]
verb_call      := [ subject ] "<" 动词 ">" 宾语 [ "(" 状语 ")" ] prep_phrase*
subject        := role | 裸词 | 引号 | $变量
prep_phrase    := "[" 介词 "]" 介宾宾语
prep_block_stmt:= "[" ( "into" | "ok" | "error" ) "]" ( $变量 | verb_call ) block

trailing_block := "[ok]" block       // 0..1
                | "[error]" block    // 0..1
                | "[into]" block     // 0..N，按书写顺序
block          := "{" statement* "}"

if_clause      := "if" condition block
                  ( "else-if" condition block )*
                  ( "else" block )?
condition      := expr

each_clause    := "each" $变量 "[in]" expr each_body
each_body      := block trailing_block*

parallel_clause:= "parallel" "{" branch* "}" [ "[results]" block ]
                  [ "|>" simple_stmt ]
branch         := simple_stmt        // 尾随块仅限 [ok] / [error] / [into]

break_stmt     := "break" [ value ] [ "->" $变量 ]
call_stmt      := "@" verb_call trailing_block* [ "|>" simple_stmt ]

expr           := value | verb_call | pipe
value          := STRING | NUMBER | 裸词 | $变量 | .字段
pipe           := verb_call ( "|>" verb_call )*

fn_def         := "@" fn_template block
fn_template    := verb_call ( "|>" verb_call )*
```

`value` 位的裸词按 `STRING` 处理：词面即值，不查变量、不查映射表；变量必须显式写 `$name`，展开映射必须显式写反引号（`` `short` ``）。

关键字表：`if` / `else` / `else-if` / `each` / `parallel` / `break`。扫描器在语句起始位置优先匹配关键字；关键字作普通名词/主语时必须加引号。

### 3.1 `//` 的词法特例（含空格容忍）

`//map` / `//fn` 只有在后接区块时才是区块头。判定规则按字符序列执行，不依赖“紧跟”：

1. 读入 `//`；
2. 跳过零个或多个空格；
3. 若接下来是 `map` 或 `fn`，继续跳过零个或多个空格；
4. 若下一个字符是 `{`，产生 `MAP_HEADER` 或 `FN_HEADER` token；
5. 否则，整行按行注释处理。

因此 `//map{`、`//map {`、`// map{`、`//fn {` 都是区块头；`//map` 后无 `{` 仍是普通注释。

进入 `//map{}` 块后，块内每行按 §3.2 的 map_entry 行模式读取，直到 `}`；这些行不启动动词扫描。

### 3.2 映射项与标记符

```ebnf
短词     := [A-Za-z0-9_-]+
标记符   := "'" | "`" | "<"
长词     := 标记符之后到行尾的全部字符（不含换行）
map_entry := 短词 标记符 长词
```

- 块内每行按 `短词 + 第一个非短词字符（标记符）+ 行尾（长词）` 切分；该行不启动动词扫描。
- 标记符只能是 `'` / `` ` `` / `<`；短词后第一个非短词字符不是这三者之一时，解析期报错 `E-01`「map_entry 标记符非法」。
- 标记符只占一个字符，且不进入长词。
- 长词从标记符之后开始，到行尾结束；原样保留，不转义、不解析、不认引号，行尾是唯一终止边界。
- `'` 与 `` ` `` 是值类标记：展开为 `STRING` 节点。
- `<` 是动词类标记：展开为 `VERB_NAME` token，用于 `<>` 内单词。
- 示例：`p'a"b` → 短词 `p`、标记 `'`、长词 `a"b`；`s'my application` → 长词 `my application`；`p'it's here` → 长词 `it's here`（`'` 不是边界）；`r<read` → 短词 `r`、标记 `<`、长词 `read`。
- 正文中 `r<read` 这类“主语 + 未闭合动词”按 `E-02` 报错，提示映射定义必须在 `//map{}` 块内。

## 四、详细规则

### 4.1 主语

主语可省略（祈使句），省略时默认当前角色。主语槽允许四种形态：

- 角色：权限载体，由内核角色清单定义；
- 裸词：普通主语文本；
- 引号：需要保留空格或语义符号时；
- `$变量`：接收者，用于 `$cfg<contains>debug` 这类动词调用。

`类型:值`（如 `file:/etc/passwd`）是裸词的一种形式。语法层不拆分、不校验；整体存入 AST，由宿主加载期按 TypeRegistry / RoleRegistry 拆分与判定。

```rill
<read> config.yml
engineer <read> config.yml
auditor <review> docs/api.md
$cfg <contains> debug
```

### 4.2 动词

尖括号包裹，开放——由框架提供的方法集决定。一句一动词，多动词必须拆成管道。

```rill
<read> a.yml |> <parse> yaml |> <write> b.yml
```

### 4.3 宾语

裸词或引号。DSL 不提供数组实参语法，逗号是否表示数组由底层方法解释。

### 4.4 状语

圆括号包裹，逗号分隔为并列项，顺序保持书写顺序；每项可写 `名称:值`。组合语义由底层库解释。

```rill
<read> config.yml (utf-8,backup:daily,timeout:30)
```

### 4.5 介宾补语

方括号包裹介词 + 介宾宾语。常用介词：`[to] [with] [from] [in] [on] [into] [ok] [error]`。

`[results]` 不是通用介词，只用于 `parallel` 块级（§4.14）。

`]` 后的归约按语法位置区分，不再用“首字符”一刀切：

| `]` 后内容 | 所在位置 | 归约 |
| --- | --- | --- |
| `{` | 语句尾随 | 尾随块头，宾语 = 前置语句结果 |
| `$变量` / 裸词 | `simple_stmt` 的介宾槽 | 普通介词短语，宾语 = 后面的词 |
| `$变量` / 裸词，且后跟 `{` | 语句起始位置 | 独立形式语句，宾语 = 后面的词 |

因此 `<send> "x" [ok] user` 是普通介词短语；`[ok] $x { ... }` 是独立形式语句；`<read> a.yml [into] { ... }` 是尾随块。

### 4.6 管道

`|>` 是纯数据流变换的主路径。前一步输出即后一步的隐式输入。

规则：

- 优先一行表达；太长折行时 `|>` 留在前一段行尾，不放在下一段开头。
- 管道只传 `value`，不传 `{value, ok}`。每段执行后得到 `{value, ok}`；`ok` 在段内由 `[ok]/[error]` 消费。
- 段尾 `ok` 为真（含 `[error]` 处理后未 break）→ 下游收到当前 `$` 的 `value`。
- 段尾 `ok` 为假且无 `[error]`，或 `[error]` 内 break → 中断管道，下游不执行。
- 尾随块只覆盖本段，`|>` 之后是下一条语句，互不影响。
- 变量只在需要回头引用中间结果时使用，不鼓励。

```rill
// 同行
<read> a.yml |> <parse> yaml |> <write> b.yml

// 跨行
<read> a.yml |>
<parse> yaml |>
<write> b.yml
```

### 4.7 变量

无声明/赋值区分。`->$x` 就是“把值放进 `$x`”：外层已存在则覆盖，不存在则建局部变量。

作用域：

- 块级：块内建的变量块外不可见。
- 外层已存在的变量：子级场域直接读写，操作的是外层那个变量，不是新建局部遮蔽。
- 外层不存在的变量：子级第一次 `->$x` 时建局部变量，块外不可见。
- `parallel` 分支禁止写外部变量——共享访问通过动词封装，线程安全由底层保证。

### 4.8 `$` 即 self

`$` 是当前域的 self，不能被赋成别的名字，但可以修改其内容。

| 语境 | `$` 指代 |
| --- | --- |
| `[into]` 块内 | 进入 into 的对象 |
| `each` 循环体 | 当前迭代项 |
| `each` 级 `[ok]` | 按源序的结果数组 |
| `each` 级 `[error]` | 第一个失败轮的错误信息 |
| `[ok]` 块内 | 段成功结果 `value` |
| `[error]` 块内 | 错误信息字符串 |
| `parallel` 分支内 | 当前分支的块输出 |
| `[results]` 块内 | 按源序的结果数组 |
| 无介宾的普通语句 | 该语句的执行结果 |

区分规则：`$name` 是变量；`$`（后不跟标识符）是 self；`.name` 是 self 字段。嵌套时最近包围块优先。

### 4.9 `[into]` 作用域

`[into]` 永远带宾语，宾语位置随形式而定：

- 尾随形式：`<语句> [into] { ... }`——宾语是前置的语句结果，`]` 后直接跟 `{`。
- 独立形式：`[into] $cfg { ... }` 或 `[into] <语句> { ... }`——宾语显式写在 into 后面，再跟块。

独立形式重名禁令：`[into]$cfg{...}` 块内禁止声明与 `$cfg` 同名的变量。尾随形式无此禁令。

### 4.10 `[ok]` / `[error]` 尾随区块

动词执行返回 `{value, ok}`。`ok` 是宿主执行层给出的成败状态，DSL 只消费，不通过返回值真假判断成败。

- `[ok]`：`ok == true` 时触发，`$ = value`（即使是 `""`、`0`、`[]`）。
- `[error]`：`ok == false` 时触发，`$ =` 错误信息字符串，默认值 `"RILL DSL ERROR"`，无结构化字段。
- 数量：`[ok]` 0..1，`[error]` 0..1。
- 默认隐式 `[error]`：不写 `[error]` 时，失败默认执行 `break "RILL DSL ERROR"`。
- 顶层语句失败：中断整个 program；管道内失败：中断管道；块内失败：中断当前块。
- `[ok]` / `[error]` 是介词，`]` 的归约按 §4.5 的位置规则。

### 4.11 尾随块叠加与执行顺序

`[into]` / `[ok]` / `[error]` 可以叠加。

执行顺序：

```text
[into]（按书写顺序，0..N）→ [ok]/[error]（按 ok 触发）→ 段输出 → |> 下游
```

段输出默认值：

- 成功且无 `[ok]` → 语句结果（有介宾时为 `$` 当前值；无介宾时为语句执行结果）。
- 成功且有 `[ok]` → `[ok]` 执行后 `$` 的最终值；只有修改 `$` 才改变输出，块内其他语句值不参与。
- 失败且无 `[error]` → 默认 `break "RILL DSL ERROR"`，中断当前场域。
- 失败且有 `[error]` → `[error]` 执行后 `$` 的最终值；若块内 break 则中断当前场域。

`[into]` 失败：视为本段失败，按 §4.10 走 `[error]`；未写 `[error]` 则默认 break。后续 `[into]` 不执行。

### 4.12 条件 if

`if` 是纯条件判断，不产生动作，不挂尾随块。动作全在 `if` 块或 `else` 块内部。

条件就是 `expr`（值、动词调用或管道），**不带尾随块**。`if` 后面第一个 `{` 永远是 body。

求值结果按 truthy/falsy 判定：

- falsy：`null`、`false`、`0`、`""`、`[]`、`{}`（来自工具结果的空对象值）。
- truthy：其余一切非空、非零的值。

与 JavaScript 不同——JS 里 `[]` 和 `{}` 是 truthy，RILL 里是 falsy。

`if` 不参与管道，只能作为独立语句。支持 `else-if`（连字符形式）。

```rill
if $cfg <contains> debug=true {
    <send> "on" [to] user
} else-if $cfg <contains> release=true {
    <send> "release" [to] user
} else {
    <send> "off" [to] user
}
```

### 4.13 循环 each

```rill
each $file [in] <search> *.yml (recursive) {
    <replace> localhost [with] prod (global) [in] $file
}
```

- `[in]` 是普通介词，带宾语 `expr`。
- `each $f [in] xs` 中 `xs` 是裸词，按字符串处理（单元素数组）；若意图是变量，应写 `$xs`。该写法会触发提示 `W-01`（§4.20）。
- 判定顺序：
  1. 从句求值为 `null` → error，走 `[error]`（或默认 break），循环体不执行。
  2. 从句求值为数组 → 正常遍历。
  3. 从句求值为其他非数组值 → 单元素数组，执行一次。
- 每轮执行块，得到 `{value, ok}`；轮内 `[error]` 处理且未 break → 该轮算成功，元素 = 处理后 value；轮内无 `[error]` 或 `[error]` 内 break → 该轮算失败，元素 = `null`，循环继续下一轮（除非 `[error]` 内显式 break 整个 each）。
- each 块输出 = 按源序的数组，长度 = 轮数，失败轮占 `null`。
- each 级 `[ok]`：所有轮都成功才触发，`$` = 结果数组。
- each 级 `[error]`：有任一轮未处理失败才触发，`$` = 第一个失败轮的错误信息。

```rill
each $file [in] <search> *.yml {
    <replace> localhost [with] prod
} [ok] {
    <send> "全部完成" [to] user
} [error] {
    <send> "过程中出错" [to] user
}
```

### 4.14 并行 parallel

```ebnf
parallel_clause := "parallel" "{" branch* "}" [ "[results]" block ]
                   [ "|>" simple_stmt ]
branch          := simple_stmt   // 尾随块仅 [ok] / [error] / [into]
```

- 块内一行一句，每句可以是复杂语法。
- 可用外部变量；块内定义的新变量块外不可见；禁止分支写外部变量。
- 分支内 `$` = 当前分支的块输出，不是最终数组。
- 分支内 `[error]` 处理且未 break → 该分支最终状态为成功；break → 该分支失败。
- `[results]` 只用于 `parallel` 块级，全部完成后触发一次；`$` = 按源序的结果数组，长度 = 分支数。成功分支元素 = 块输出 value；失败且未处理 = `null`；失败但分支内 `[error]` 处理且未 break = 处理后 value。
- `[results]` 永远触发，不论整体成败；它只管值，不携带状态字段。
- parallel 块输出 = `[results]` 的 `$`；未写 `[results]` 时 = 默认结果数组。
- 非 `parallel` 语句写 `[results]`，或分支内写 `[results]` → 解析期报错。

```rill
parallel {
    <read> a.yml [error] { <send> "a failed" [to] user }
    <read> b.yml
} [results] {
    <send> "完成" [to] user
} |> <write> out.yml
```

### 4.15 break

- 场域：由所在区块决定。任何区块内触发 break 都中断当前管道；管道内中断管道，块内中断块，顶层中断整个 program。
- 值：默认字符串 `"RILL DSL ERROR"`（隐式 `[error]` 的默认实现）。用户可自定义，值最终落字符串。
- 捕捉：`break <值> -> $var`，值传给当前场域外部，由外部变量捕捉；无变量接则丢弃。
- 顶层独立语句的 break：中断整个 program。
- `break` 后的值只能是 `value`（`STRING` / `NUMBER` / 裸词 / `$变量` / `.字段`）之一，不含动词调用；裸词按字符串处理。要传动词结果先 `->$x`，再 `break $x`。

### 4.16 引号与转义

| 场景 | 规则 |
| --- | --- |
| 单引号 `'...'` | 纯字面量，不做任何转义，首选。内部所有字符原样，包括语义符号。不允许包含单引号——需要时用双引号。压缩态和展示态都有效。 |
| 双引号 `"..."` | 字面量，支持转义：`\"` `\\`。可包含单引号。不做插值——`$var` 是字面文本。 |
| 裸词中的语义符号 | 兜底用反斜杠转义：`\[` `\]` `\(` `\)` `\<` `\>` `\{` `\}` `\$` `\\`。单引号能解决的尽量用单引号。 |
| 拼接 | 引号段与变量直接相邻即拼接：`"查询到 "$count" 条"`。 |

展示态：保留转义序列本身，不还原为字面字符。展示态做三件事——加空格、按块缩进、展开映射表。展开映射时，值类长词按双引号规则输出：含空格、`"`、`\` 或语义符号时加双引号并转义，否则输出原文；这是“展开映射”的规则细化，不是第四种变换。

双向可逆：

- 压缩 → 展示：去空白后的 token 序列，加空格、缩进、展开映射表。
- 展示 → 压缩：去掉空白（引号内保留）、查映射表把长词换短词。
- 可逆性保证：一个长词只对应一个短词；同一长词在可见链上仅保留最近绑定。

### 4.17 映射表 `//map`

声明：

```text
//map{
cfg`configuration
r<read
p'a"b
s'my application
}
```

词法（与 §3.2 一致）：

- `//map{` 是区块开始标记；`//map` 后无 `{` 是普通注释。空格容忍见 §3.1。
- 每行格式：`短词 + 第一个非短词字符（标记符）+ 行尾（长词）`；块内行不启动动词扫描。
- 短词：字母、数字、`-`、`_`。
- 标记符：`'`、`` ` ``、`<`，只占一个字符，不进入长词；短词后第一个非短词字符不是这三者之一 → 解析期错误 `E-01`「map_entry 标记符非法」。
- 长词：标记符之后到行尾的全部字符，原样保留，不转义、不解析、不认引号；行尾是唯一终止边界。
- 值类标记 `'` / `` ` `` 展开为 `STRING` 节点；动词类标记 `<` 展开为 `VERB_NAME` token。
- 位置：只允许出现在语句边界（顶层或块内，不能在管道续行中间）。推荐头部。
- 生效范围：所在块内从定义处之后到块结束。内层优先。
- 重复：同块内重复短词报错；不同块可各自定义。
- 可见链唯一：同一长词在可见链上仅保留最近绑定，内层定义即覆盖外层；反向映射从内到外取首个命中。

引用：

- `<>` 内的单词和反引号包裹的裸词共用一张映射表查表展开；其他裸词不查。
- 值类映射在 AST 中**统一归约为 `STRING` 节点**，不产生 `LongWord` 节点。
- 展示态展开时，值类长词按双引号规则输出：含空格、`"`、`\` 或语义符号时加双引号并转义，否则输出原文。
- AST 等价判据：忽略位置信息（span）后，两棵 AST 的节点类型与 `value` 逐一相等。`p`（长词 `a"b`）与双引号字面量 `"a\"b"` 必须得到同一 `STRING` 节点；`s`（长词 `my application`）与 `"my application"` 同理。
- 动词类映射 `r<read` 使 `<r>` 等价于 `<read>`，AST 中为同一 `VERB_NAME`。

```rill
<read> `cfg`.yml |> <replace> localhost [with] `w`-prod
```

介词映射：通常放在框架侧的 RILL.md 中（给 LLM 的使用指南），不进脚本头部。

### 4.18 函数定义 `@`

定义只在 `//fn{}` 区块内，与 `//map{}` 并列放脚本头部。正文 `@` 只用于调用。

```ebnf
fn_block    := "//fn" "{" fn_def* "}"
fn_def      := "@" fn_template block
fn_template := verb_call ( "|>" verb_call )*
call_stmt   := "@" verb_call trailing_block* [ "|>" simple_stmt ]
```

- 函数**没有名字**；`@` 之后直接写一个 `verb_call` 形状（D-022）。
- 签名是由模板第一段 `verb_call` 机械导出的**形状键**：动词词面、主语位身份（无 / 参数位 / 常量位）、宾语位身份、常量位的值、状语名称集合、介词名称与书写顺序。
  - 参数位的**个数与出现位置**进签名；参数变量名、默认值、状语的值不进签名。
  - 常量位按值的字符串形态比较：`'ok'`、`"ok"`、`ok` 是同一个值；主语写死具体角色名时按常量位处理。
  - `|>` 之后的模板段不进签名；它们只是模板的执行步骤。
- 调用点用同样的办法构造形状键，与函数表求**精确相等**；不做最近匹配、不做优先级、不做运行时重载。
- 同一 `//fn{}` 内两个定义形状相等 → 加载期错误 `E-03`，指向后一个定义；禁止覆盖。仅差参数变量名、默认值或状语值的两个定义也是同形。
- 调用形状无候选 → 加载期错误 `E-04`，Hint 列出同动词的已定义形状，错误串不携带名字。
- 多候选（防御宿主注入或合并绕过同块检查）→ 加载期错误 `E-05`，列出全部候选与定义行。
- 模板各成分可为 `$变量` 或 `$变量?默认值`；默认值只决定该参数位可省略，不参与区分形状。
- 实参绑定按位置：模板第一段里每个参数位在调用里都要写值。同一参数在模板多处出现时，调用点每个位都要写值且各次值必须相等，否则运行期错误 `E-06`；不引入空位语法。
- 仅尾部可选位可省略：默认值只允许出现在尾部；中间跳过或个数不符 → 加载期错误 `E-LOAD-FN-ARITY`。带默认值的介宾可整段省略，出现时仍按位绑定。
- 状语按名称集合匹配，顺序无关、重复不计，不比较状语的值。
- 介词按名称与顺序精确匹配；`[into]` / `[ok]` / `[error]` / `[results]` 是尾随块或结果块，不是介宾，不进签名。
- 模板不带尾随块；尾随块只能写在调用上。
- 函数体最后一条语句的段输出即返回值；空体返回 `null`。
- 正文出现 `@ "name"` 旧形态 → 解析期错误 `E-07`，错误位置在字符串 token，并给出迁移提示；不保留按名字查找的回退路径。`@` 后不得以字符串开头：常量主语写裸词，参数主语写 `$变量`，无主语直接写 `<动词>`。

```text
//fn{
@ <read> $path |> <parse> yaml {
    <read> $path |> <parse> yaml
    <write> $path
}
}

// 正文调用：形状与定义同形，每个参数位都写值
@ <read> "config.yml" |> <send> "完成" [to] user
```

### 4.19 空格规则

| 场景 | 规则 |
| --- | --- |
| 传输/存储 | 不含空格，符号即边界 |
| 展示 | 各成分间加一个空格，按 `{}` 层级缩进 |
| 引号内部 | 单引号按字面；双引号按字面（仅 `\"` `\\` 转义） |
| 有符号在 | 空格可去（如 `if$cfg{...}`） |
| 连词之间 | `else-if` 用连字符，不用空格 |
| 尾随区块 | 与前面语句/块同一行，不换行 |
| 管道续行 | `|>` 留在前一段行尾 |
| `//` 头 | `//` 与 `map`/`fn`、`map`/`fn` 与 `{` 之间允许零个或多个空格（§3.1） |

### 4.20 错误与提示

| 编号 | 类型 | 触发位置 | 文案 |
| --- | --- | --- | --- |
| `W-01` | 警告（lint，不报错） | `each` 的 `[in]` 位是裸词 | 裸词 `xs` 按字符串处理，若意图是变量请写 `$xs` |
| `E-01` | 解析期错误 | `//map{}` 行内，短词后第一个非短词字符不是 `'` / `` ` `` / `<` | map_entry 标记符非法 |
| `E-02` | 解析期错误 | 正文出现 `r<read` 这类主语 + 未闭合动词 | 动词未闭合；映射定义必须在 `//map{}` 块内 |
| `E-03` | 加载期错误 | 同一 `//fn{}` 内两个定义形状相等 | 函数形状重复；Hint 给出两份形状与首个定义行 |
| `E-04` | 加载期错误 | 调用形状在函数表中无候选 | 未声明的函数形状；Hint 列出同动词已定义形状 |
| `E-05` | 加载期错误 | 调用形状命中多个候选 | 函数形状二义；列出全部候选与定义行 |
| `E-06` | 运行期错误 | 同一参数位在模板多处出现，调用给出的值不相等 | 参数绑定冲突 |
| `E-07` | 解析期错误 | `@` 后出现字符串（旧 `@ "name"` 形态） | 函数已去名；`@` 后直接写 verb_call，并给出迁移提示 |

`W-01` 只提示，不改变语法合法性；`E-01` / `E-02` 均为解析期错误，报错带行列号。

## 五、边界声明与宿主接口

以下为 RILL 的已知边界，不是缺口：

1. 不支持授权头：工具白名单和权限由内核角色配置控制，脚本无权声明。
2. 不支持资源上限声明：steps / time / bytes / 并行分支数 / 搜索深度等由引擎 ExecLimits 控制，截断元数据由工具返回值携带。
3. 不支持数组实参语法：逗号是否数组由底层方法解释。
4. 不支持插值：双引号内 `$var` 是字面文本。
5. DSL 不做类型判断：类型、错误处理由底层方法决定。
6. DSL 不做工具调用绑定：SVO 槽到实参的映射由 VerbRegistry 决定；函数调用按 §4.18 的形状与位置绑定。
7. DSL 不做缩进规则：展示态格式化由 pretty printer 实现，RILL 内置一个默认 printer。
8. 未知动词加载期报错，未知介词解析期报错。

宿主接口：

| 注册表 | 内容 | 使用阶段 |
| --- | --- | --- |
| TypeRegistry | 类型名 + 值形态（如 `file` / `net`） | 加载期拆分 `类型:值`、校验类型 |
| RoleRegistry | 角色名 + 权限 | 加载期校验主语角色 |
| VerbRegistry | 动词名 + 签名 + 失败报告方式 | 加载期校验动词，执行期归一化为 `{value, ok}` |

加载期 = parse 完成之后、exec 之前。解析器核心只产 AST，不查注册表、不拆分 `类型:值`、不校验角色/动词/类型。两个宿主得到同一 AST，合法性差异在加载期体现。

## 七、解析器实现要点

1. 预处理 `//map` / `//fn` 区块，建立映射表与函数形状表。`//` 的空格容忍按 §3.1。
2. 关键字优先：语句起始位置先查关键字表（`if` / `else` / `else-if` / `each` / `parallel` / `break`），命中即按对应语句类型解析。
3. 零空格扫描：符号即边界，字符扫描状态机：
   - 非符号字符 → 主语（直到 `<`），先查关键字表
   - `<` → 动词（直到 `>`）
   - `>` 后非符号 → 宾语（直到 `( [ -> |> 行尾`）
   - `(` → 状语（直到 `)`）
   - `[` → 介宾（直到 `]`），`]` 后按 §4.5 的位置规则归约
   - `->` → 赋值
   - `|>` → 管道续行（留在前段行尾）
   - `{` → 块开始
   - `@` → 函数调用（按整句形状查函数表）
   - `$` → 后跟标识符是变量，不跟是 self
   - `` ` `` / `'` / `<` 在 `map_entry` 内是标记符，按 §3.2 切分
4. 引号处理：单引号纯字面；双引号仅 `\"` `\\` 转义；裸词中 `\` 转义语义符号。
5. 换行：语句边界，保留。
6. 报错阶段：未知介词、`[results]` 误用、旧 `@ "name"` 形态 → 解析期；未知动词、形状重复/未声明/二义、arity、默认值非尾部 → 加载期；绑定冲突 → 运行期。
7. 展示态格式化：展开映射、补空格、按 `{}` 缩进、尾随区块同一行。值类长词按双引号规则转义；规范不写死缩进细节。

## 八、设计原则

1. 零冗余传输：存储/传输不含空格，每个字符都有语义。
2. 符号唯一：每种成分有唯一符号；方括号仅用于介宾和 `[into]` / `[ok]` / `[error]`；`[results]` 仅用于 `parallel`。
3. SVO 语序：符合自然语言，主语可省（祈使句）。
4. 一句一动词：多动词拆管道。
5. 管道 + 尾随区块是重心：良好脚本以链式结构为主，变量和独立语句是少数。
6. 可扩展：状语和介宾可无限叠加，动词表开放。
7. LLM 友好：规则极少，LLM 记忆符号规则 + 当前动词表 + 角色清单即可生成。
8. 展示可读：自动加空格、缩进，尾随区块同一行。
9. 压缩是手段：零空格 + 符号边界 + 映射表，三层叠加。
10. 双向可逆：压缩态与展示态纯机械转换，长词唯一 + 可见链最近绑定保证可逆。
11. DSL 不做类型判断：类型、错误处理、工具调用绑定、资源上限由底层决定；函数调用绑定由 §4.18 定义。
