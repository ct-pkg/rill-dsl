## 争点

## 判决

`upheld`。文法：

```
emit_stmt    := "emit" STRING emit_payload
emit_payload := json_value
json_value   := json_object | json_array | expr
json_object  := "{" json_members? "}"
json_members := json_pair ("," json_pair)*
json_pair    := STRING ":" json_value
json_array   := "[" json_values? "]"
json_values  := json_value ("," json_value)*
```

规则：`{`/`[` 只在 emit payload（含嵌套值）位置作字面量起始，表达式其他位置 `[` 只作索引后缀；键必须是字符串字面量；无尾随逗号；重复键是加载期错误；JSON 内部 NEWLINE 忽略，`emit STRING` 与 payload 之间的 NEWLINE 也忽略；payload 后不接后缀。

## 生效范围

下一版规范 §3.2/§4 R7/§7/§8 示例 4；M7 与词法的 `:`/`,` 标点。不含通用对象字面量。

## 理由

`expr` 的任何分支都不以 `{` 起始，`emit STRING` 后也没有块选项，因此 `{` 的角色由位置唯一决定，不需要回溯。拒绝反证席的“payload 必须单行”：该限制不带来消歧收益（`emit` 后的 `{` 只有对象一种解释），只增加无谓报错；JSON 内换行抑制与 `(`/`[` 内抑制同构，不是上下文敏感规则。值位采纳 `expr` 而非仅 `postfix_expr`，因为 `,`/`}`/`]` 都不是 `expr` 的延续 token，`"count": n + 1` 安全且避免迫使作者先 `let`。

## 失效条件

实测 payload 内出现管道或深层嵌套导致可读性显著下降 → 把 `json_value` 收窄到 `unary_expr`（实现级回退，不改 emit-only 位置约束）。
