## 判决

`upheld`（用户裁定）。文本层面接受；实现层面因无 parser 与门禁，状态保持 `unverified`，不得写成“已验收”。

## 生效范围

- 只约束调用形态：`name arg...`；括号仅分组与 `fn` 参数表。
- 约束 [S-001](../spec/S-001-call-form.md) 与 M1/M6 的调用语法。
- 不覆盖：`postfix ()` 是否删除（P-002）、零参调用、工具/函数同名、嵌套实参、括号单原子（P-018）。
- 范围外不得引用本决策来宣称“整个文法已定稿”。

## 理由

1. 两套并列写法让 LLM 必须额外记住“工具用空格、函数用括号”，增加 few-shot 负担。
2. 括号形态与“括号只分组”的直觉冲突；统一后，括号只承担分组作用，语法角色单一。
3. 最常见的工具调用（`read "path"`、`grep "foo" "file"`）形态不变，token 成本不增加。

## 失效条件

- M1 真实 LLM 验收中，同一模型、同一提示下调用形态写错 ≥3 次，并按既定口径切换到路径 B（括号调用）作为退路；届时本决策应标 `superseded` 并新开 `D-*`。
- 用户明确撤回「空格替代括号」。
