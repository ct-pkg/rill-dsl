## 争点

是否引入 `x = expr` 赋值（是否要求 `let mut`）、`for` 变量语义、`break`/`continue` 是否进 M4、`while` 是否进 MVP。

无 verify.json。裁判重跑确认 v0.1 只有 `let`（§3.2 L59-L72）、无赋值；CT 规范 L1987/L2005-L2006 为 item 值拷贝、写 item 不回写；L2231 为 CT `into` 允许 `$ = expr`（DSL 不沿用）。无解释器，行为为规则定义。

## 判决

`upheld`（拆分：赋值 + `let mut` + `for` 变量不可变 + `break`/`continue` 采纳；`while` 否决）。

1. 新增赋值语句 `IDENT "=" expr`，只能写 `let mut` 声明的同一函数帧局部变量；普通 `let` 不可变；`let`/`let mut`/`fn` 参数/`for` 变量是唯一定义点，赋值只存不建名。
2. 加载期检查：目标未定义 → 报错并提示补 `let`；目标非 `mut` → 报错并提示 `let mut x = ...`；赋值是语句不是表达式（`if x = 1` 报语法错误并提示 `==`）；闭包捕获变量不可赋值；`$` 不可赋值。
3. 同一作用域内 `let` 重名报错，禁止用遮蔽冒充累加。
4. `for` 变量每轮是不可变值拷贝；要改就 `let mut v = item`。
5. `break`/`continue` 只允许出现在 `for` 体内，不能跨 `fn` 边界；`into`/`if` 不是循环边界。
6. **`while` 不进 MVP**；重开条件见下。
7. `ExecLimits` 不新增字段；补计数口径：每次迭代至少 +1 步（空体亦然），`continue` 不重置计数，超限返回 `ok=0` + `error_kind=limit`。

## 生效范围

下一版规范 §3.2、§4 R5、§6.3；M4 与 golden。不含 `while` 与块级恢复。

## 理由

判据 5 是赋值必须存在的硬理由：没有赋值时 LLM 会写 `let report = report + chunk`，每轮新建遮蔽绑定，脚本退出 0 却写出空结果。`let mut` 采纳主张席而非反证席的“任意绑定可赋值”：后者让所有绑定默认可变，失去“这个名字此后不变”的阅读保证，且没有静态边界；漏写 `mut` 得到加载期、带修法的错误，一次可改，对现有示例零 token 成本。`for` 变量值拷贝与项目已裁的 item 值拷贝一致。`continue` 采纳主张席：反证席以“跳过自增导致死循环”反对，但该风险只存在于 `while`，`for x in xs` 没有自增可跳，且 `continue` 是“跳过坏项”的唯一手段。`while` 否决：两席一致，空体循环只能靠 `max_steps` 粗粒度兜底，且重试已由用户裁给工具参数、轮询应由工具带 timeout。

## 失效条件

- 出现具名任务无法用 `for` + 工具级 wait/paginate + `|?` 表达，且必须在单次执行内完成 → 重开 `while`，采用“每次迭代计 1 步、超限 `error_kind=limit`”的最小形态。
- 实测漏写 `mut` 比例极高、摩擦造成可归因失败 ≥3 次/同提示 → 重开 `mut` 门槛（不改“赋值只存不建名”）。
