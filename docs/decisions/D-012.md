## 判决

`upheld`（快照；补反证席的稳定性与扩张审批）。

1. 加载时构造不可变 `PolicySnapshot`：`policy_generation`、allow/deny/emit 集、每个工具的 constraint version、`(name, handler_id)`。
2. 一次 `dsl_exec` 全程只读该快照；加载期集合校验与执行期参数校验使用同一代。
3. 热更新 = 构建新快照 + 原子指针替换，只影响后续加载；进行中的执行不受影响。
4. 强杀：内核可在“下一次工具调用边界”中止在飞执行（不打断 handler 内部）；结果 `ok=0` + `error_kind=revoked`，保留已完成步骤的返回值。
5. 结果回显 `policy_generation`；`DslResult` 增该字段。
6. 脚本原子性：执行 AST 的内容哈希必须等于校验时哈希，否则 `E_SCRIPT_CHANGED`。
7. 策略扩张（加工具、放宽约束、加事件）必须人工审批，否则拒绝加载 `E_POLICY_EXPANSION_UNAPPROVED`；收缩可只写审计日志。
8. 审计：每次热更新产出一条 diff（`added=[...] removed=[...] gen=N`）。

## 生效范围

下一版规范 §5.4、§6.3、§13 热更新段；M8 与 golden。不含订阅方派生执行的快照取点（属 P-014 事件因果链）。

## 理由

实时查有两类可推导缺陷：加载期允许、执行期收紧导致脚本中途失败（半成品状态，R4 不保证回滚）；约束版本在加载后被放宽，脚本获得加载期未审权限。快照是唯一能同时满足判据 1/2 的结构；成本席的“不可变 Policy + 指针交换 40–60 行”给出最低成本实现。判据 3 补反证席：工具名在 AST 是静态字面量，但 handler 指针可被替换，故必须绑定 `(name, generation, handler_id)` 并校验脚本哈希。判据 4 补反证席：L512 的“审批**或**审计”会让扩张也只需事后日志，必须拆成“扩张审批 / 收缩审计”。反方“撤销必须即时”不成立：即时撤销与加载-执行原子一致不可兼得；用一次调用边界强杀把延迟压到有界，且选择权在内核。

## 失效条件

- 运维要求撤销即时生效，且强杀成本高于“实时查 + 每步重校验” → 重开，但必须保留 handler 身份与脚本哈希绑定。
- 快照导致长脚本在 `timeout_ms` 内仍可用已撤销工具 → 收紧强杀边界或缩短 `timeout_ms`，不得取消快照。
