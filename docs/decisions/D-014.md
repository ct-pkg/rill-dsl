## 争点

第三层参数约束要写到什么强度：路径前缀是否需要 canonical 化与打开时复核、命令白名单是否必须 argv 化、域名/emit/双通道/重复键是否纳入。

## 判决

`upheld`（分档：必做 / 不做 / deferred）。

**必做（规范写可观测行为，不绑实现）**

1. 路径：判定对象为解析后的绝对路径；界内 = 等于 root 或以 `root + "/"` 为前缀；写不存在的文件时解析父目录 realpath 并校验 basename 不是 symlink；判定与打开同源（`openat` 拿 fd 或逐段 `O_NOFOLLOW`），handler 接收已校验 fd/路径，不得再解析原始字符串。夹具：`/workspace/../../etc/passwd` 拒、`/workspace/link→/etc` 拒、`/workspace/link→/workspace/sub` 允、`/workspace/new.txt` 允、`/workspace-evil/x` 拒。
2. 命令：exec 类工具参数为 `argv: array<string>`，禁止 `shell: true` 一类开关，无 shell 解释器；约束补 `CONSTRAINT_ARGV0_EXACT`（绝对路径）与 `CONSTRAINT_ARGV_PREFIX`；`sh -c`/`bash -c`/`env`/`xargs` 仅允许在专门高危工具内且必须 `requires_approval`；管道/重定向不属于 MVP 的 exec 能力。
3. 域名：host 规范化（小写、punycode、去尾点）、标签边界精确或后缀、scheme 仅 https、端口显式、禁 userinfo、重定向逐跳复核且有上限、DNS 解析结果钉住不再二次解析、禁代理；`file://`/`gopher://` 拒。
4. emit：新增 `max_emit_bytes` 与 `max_payload_depth`（规范给具体默认数字）；每条 `# emit:` 可选 payload schema（顶层字段名 + 标量类型）；外部订阅方只接收标了 `external_egress` 的事件；超限/不合 schema 返回 `ok=0` + `error_kind=limit|emit_schema`，不得静默丢事件。
5. 双通道：约束必须覆盖 `args_json` 与 `ctx_json`；隐式 `$` 必须有名字与约束绑定，否则 `E_UNCONSTRAINED_ARG`。
6. 解析：args JSON 只解析一次，重复键 `E_DUP_KEY`；约束看到的对象与 handler 入参是同一份规范化结果。

**不做**

- 默认 `additionalProperties: false` 的严格 JSON Schema（会把 LLM 常见多余字段变成重试，负收益）；schema 逐事件选入。

**deferred（undecidable）**

- 跨 exec payload taint（能力/污点标签）——见 PENDING P-021。
- 外部授权主体（`grant_set`/`principal_id`）——见 PENDING P-020。

## 理由

判据 1 上，只做字符串前缀可被 `..`、`/workspace-evil`、指向界外的 symlink 三路绕过（主张席与反证席同向），而 CT 的 `realpath` 要求路径存在，写新文件必须解析父目录，故 canonical + 组件边界 + 父目录解析是“最低可主张”。成本席主张“本期不主张 TOCTOU 硬化”，我拒绝：一旦规范写了“路径前缀”却不含打开时复核，就是虚假安全；正确做法是规定可观测行为（夹具全拒），实现可选 `openat` 或 `O_NOFOLLOW`。判据 3 三席一致，且 CT 自身字符串 `system()` + `sh_quote` 是“名字白名单盖不住参数面”的现成反例。判据 4 的规范化成本低（成本席估 15–30 行），采纳。判据 5 由 `max_output_bytes` 的注释边界（L292）与深拷贝放大（L194）推出，必须新增字段。判据 6 由 `:158` 只做浅校验、重复键可导致“校验对象 ≠ 执行对象”推出。

## 失效条件

- workspace 为 symlink 挂载且无法在根上解析，导致夹具五件套系统性误杀 → 重开路径规则，但保留“解析后仍在界内即可”，不得退回字符串前缀。
- 实测 emit schema 造成大量重试 → 收窄为仅字节/深度上限（schema 逐事件选入不变）。
- 启用外部 webhook 订阅方或发生 taint 事件 → 重开 P-021。
