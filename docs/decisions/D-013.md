## 判决

`upheld`（内核；补参数绑定与主体缺口声明）。

1. 审批 100% 在内核；DSL 不加 `approve` 语句、不加 `# approval:` header、不加审批表达式。`# approval:` 按未知 header 报错。
2. DSL 侧唯一接口是 `ToolDef.requires_approval`（bool 或内核谓词 id），脚本不可覆盖。
3. 审批对象 = `(policy_generation, tool, canonical_args_hash, nonce)`；执行前以常量时间复核；参数变化 → `E_APPROVAL_STALE`，重放 → `E_APPROVAL_REUSED`，handler 均未调用。
4. 审批结果走错误通道：`ok=0` + `error_kind=approval_required|approval_denied`，脚本按 R4 中止块；不做暂停/恢复，不把审批变成脚本可捕获的值。
5. 审批等待不计入 `ExecLimits.timeout_ms`；结果含 `approval_wait_ms`。
6. 同一次执行内按 `(tool, args-hash)` 缓存审批结果，避免循环内重复弹窗。
7. 审批理由由内核按工具名 + 参数生成，不接受脚本提供的理由字符串。
8. 新增“Rill 在 agent 运行时中的位置”一节：内核所有（主循环、模型调用、上下文压缩、记忆、自修复、审批、调度、工具注册与策略、订阅方注册）；DSL 所有（单次执行的语法与语义）。归属规则一条：任何需要“跨语句持久状态”或“挂起后恢复”的能力归内核。
9. 规范必须写明：没有外部主体（`principal_id`/`grant_set`）时，审批只绑到工具与参数，不绑到“谁”，该缺口见 PENDING P-020。

## 生效范围

下一版规范新增边界一节、§6.1 `ToolDef`、§11 错误示例；内核接口与 M8。不含主体模型与外部授权集。

## 理由

判据 4 的归属规则同时排除审批、并行调度、重试循环、记忆读写，机械可判。审批不能进 DSL 的核心原因是没有暂停/恢复语义：`dsl_exec` 是同步单次调用，DSL 级 `approve` 只能靠解释器保存 continuation，等于把内核状态机塞进脚本语义。判据 2 采纳反证席：工具级审批只暂停不缩小能力，批准一次 `write` 不覆盖任意参数，故绑定规范化参数哈希与 nonce。反方“内核审批对模型不透明、逐次审批耗尽耐心”不成立：透明度用 `ToolDef.description` + 拒绝文案，耐心用同次执行缓存与内核批量授权，这些都在内核配置，反证其不属于 DSL。

## 失效条件

- 出现必须“执行中阻塞等待人工确认”的真实流程 → 重开，评估 `approval_required` + 内核重跑；不在 DSL 内引入暂停。
- 内核接口 CR 明确 `dsl_exec` 主体字段 → 一并重开 P-020，把审批绑定到 principal。
