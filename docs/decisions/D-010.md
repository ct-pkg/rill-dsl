## 判决

`upheld`。R4 改写为：

- **R4.0** 运行时失败是附着在产生它的那次 call 上的控制信号，不是值，不能存变量、比较或当参数。
- **R4.1** 信号向外传播到最近的块边界（`if`/`for`/`into`/`fn` 体），该块中止，信号继续向外。
- **R4.2** 唯一消费者是 `|?`，且只消费它左侧那个 call 的信号；左成功时右侧不执行。
- **R4.3** 右侧也失败时信号继续向外，诊断同时给出两侧调用位置。
- **R4.4** `|?` 不是 handler 作用域，不捕获更早管道阶段、外层块或右侧内部嵌套调用的失败。
- **R4.5** `fn` 边界：fn 体内失败中止 fn 体，该 fn 调用失败；调用方的 `|?` 可消费它。
- **R4.6** MVP 只有调用级降级，**没有块级恢复**；没有 try/catch、没有错误值、没有恢复执行。一个失败要么中止块，要么被恰好一个 `|?` 变成值。
- 失败行为表：普通调用（可捕获类/不可捕获类均中止块）、`|?` 左操作数（可捕获类执行右侧并置 `degraded=1`；不可捕获类不捕获）、`emit`（~~永不失败~~ **已由 D-014 与 04 §3 取代**：无订阅方/队列满丢弃并记日志；字节/深度超限或 schema 不符为可见失败，`limit`/`emit_schema`）。
- `|?` 不回滚任何已发生的副作用；需要回滚由工具提供补偿。
- `DslResult` 增 `degraded`（0/1）与 `error_kind`；`ok=1 && degraded=1` 表示“完成但有降级”。

## 生效范围

下一版规范 §4 R4、§9“明确不做”、§10 错误传播行；M2/M3 解释器与诊断。与 D-007 配套，不得单独引用。

## 理由

现行 R4 的第二句“if/for/into/fn 块内失败，整个块中止”在含 `|?` 左操作数时不成立，第三句“不做 try/catch”在已有调用级捕获后也失真；反证席“不字面矛盾，但已成一句错话”的定性准确。改写保留“默认中止”这一半，补上唯一例外及其边界，使每条失败路径有唯一归属。补失败行为表、`degraded`、不回滚声明，是为了避免“脚本成功但全走兜底”对调用方不可见；用“无块级恢复”替代“不做 try/catch”，是把缺口写明而不是用否认掩盖。

## 失效条件

内核需要块级恢复（批量任务跳过坏项）成为刚需 → 重开本条；但需用户先推翻讨论稿 §2.3 的“只用 `|?`”更正。
