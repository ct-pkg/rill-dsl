## 争点

无 `# allow:` 时是继承注册表级白名单（默认全开），还是默认拒绝；`# allow: *` 与 `# deny:` 单独出现如何处理。

## 判决

`upheld`（默认拒绝）。

1. 无 `# allow:` → 有效集合为空，加载期拒绝；错误含位置 + `no '# allow:' header; tools are denied by default` + `Available: ...` + 修法。
2. `# allow: a, b` → 仅该集合；`# deny:` 优先于 allow。
3. `# allow: *` → 等价旧的“继承注册表级”，但必须显式、可 grep，并产出一条审计记录（脚本路径、有效集合大小、理由字段）。
4. 声明了 `# allow:` 但列表为空，与不写 header 同义（拒绝）。
5. `# deny:` 单独出现（无 `# allow:`）→ 加载错误，提示补 `# allow:`；不得静默变成空集。
6. 第 2/4 条所述“列表为空”指**语法上为空**（`# allow:` 之后没有任何名字）。列表**非空但全部未注册**时，有效集为空但脚本仍正常加载，不适用第 4 条的“与不写 header 同义”；未注册名不授予权限、不报错、不产生加载期 kind（细化见 [06 §2](../spec/dsl/06-security.md)、PENDING P-023）。本条只作区分说明，不改变第 1–5 条的三态结论。
7. 默认拒绝只改第二层默认值，不改第一层注册表。
8. 规范必须写明诚实边界：header 由脚本作者自书，默认拒绝阻止的是“无意识授权”和“静默扩大”，不阻止作者显式申请危险工具；外部授权主体不在本条范围（见 PENDING P-020）。

## 生效范围

下一版规范 §3.1、§5.2、§11；M8 与 loader golden。不含外部 `grant_set`/`principal_id`。

## 理由

判据 3 的实测量级支持现在改：仓库零脚本、五个示例全部自带 header，迁移成本为零。反方最强的“改默认值违反 §13 向后兼容（L510）”不成立：兼容义务的载体是已存在脚本，实测为 0，且 §13 约束的是“旧脚本不写新语法照常跑”，在首个实现发布前确定安全默认值不属于行为变更。反证席的“header 自授权”是真问题，但不能推出“保持默认全开”：全开会把攻击面从“作者显式申请”扩大到“作者忘记写”。该缺口按判据 7 写入诚实边界，外部授权集另行立项。

## 失效条件

- 出现任一外部方按 v0.1 写的 headerless 脚本需要继续运行 → 重开，评估“告警过渡 + `# dsl-version` 分支”；不得直接把“继承注册表”恢复为缺省。
- 实测 LLM 漏 header 率高到每次任务多 ≥2 次往返 → 重开，评估“默认最小只读集 + 审计”。
