## 判决

`upheld`。采纳：

```
tool_call    := IDENT arg+
arg          := postfix_atom
postfix_atom := atom suffix*
suffix       := "." IDENT | "[" expr "]"
atom         := IDENT | STRING | NUMBER | BOOL | NULL | "$" | "(" expr ")"
```

规则：实参位不再发生空格应用；`f g "x"` = `f(g, "x")`；嵌套写 `f (g "x")`；表达式实参写 `f (a + b)`；`into` 在实参位按上下文关键字终止调用；`f(a)(b)` = `f(a, b)`，写入规范不为它单设禁令。

## 生效范围

下一版规范 §3.3 与 §7 的 `arg`/`primary`/`postfix_expr`；M1 实参解析与 golden。不含保留字全集、零参调用（见 D-005）、错误格式。

## 理由

递归实参对“两个 IDENT 起头的常见调用”无解：`copy src dst` 同时是 `copy(src, dst)` 与 `copy(src(dst))`，讨论稿 L122 已记录 `f a b c` 四种树；贪心策略也不能消灭歧义，只会把问题推迟到运行期。非递归实参 1 token 前瞻即可唯一解析，主流形态零 token 成本，代价只落在低频嵌套的一对括号上。反方“为罕见嵌套牺牲 token 不划算”不成立：真正的代价不是 token，而是 `grep "TODO" read path` 这类输入在递归文法下两棵树都过 schema 浅校验、脚本静默算错。

## 失效条件

M1 用真实 LLM ≥20 条脚本统计，`f (g x)` 形态占比高且强制括号导致首次解析失败率显著高于基线 → 重开 B1-1；未取得语料前不得以印象重开。
