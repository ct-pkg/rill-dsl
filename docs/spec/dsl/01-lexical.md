# 01 词法

> 规范版本 `v0.1 rev.1`；状态 `unverified`。本卷对应旧文 §2，改动依据见每节 `[D-xxx]`。

## 1. 源文本

- 编码 UTF-8；不接受 BOM（出现即 `E_SYNTAX`）。
- 行尾 `\n` 或 `\r\n`，统一归一为 `\n`；单独的 `\r` 是语法错误。
- 源文本以虚拟 `NEWLINE` 结束；文件末尾未闭合的 `{`、`(`、`[`、字符串均报 `E_SYNTAX`。

## 2. token 类别

| 类别 | 形态 | 说明 |
| --- | --- | --- |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` | 工具名、变量名、函数名、字段名 |
| `STRING` | `"..."` 或 `'...'` | 转义 `\n \t \" \' \\ \$`；不允许内嵌裸换行 |
| `NUMBER` | `[0-9]+("."[0-9]+)?` | **不带符号**；`-` 见 §5 [D-003] |
| `BOOL` | `true` / `false` | 关键字 |
| `NULL` | `null` | 关键字 |
| `KEYWORD` | §3 列表 | 不可作标识符 |
| `PUNCT` | `\|>` `\|?` `=` `==` `!=` `<` `>` `<=` `>=` `+` `-` `*` `/` `%` `.` `,` `:` `[` `]` `(` `)` `{` `}` | 最长匹配：`\|?` 先于 `\|`；`==` 先于 `=` |
| `NEWLINE` | `\n` | 受 §6 抑制规则约束 |
| `EOF` | 文件结束 | |

`+` `-` `*` `/` `%` `==` `!=` `<` `>` `<=` `>=` `.` `,` `:` 在词法层一律产出 token，不做上下文区分；`:` 只允许出现在 header 与 emit payload 中，其他位置由文法拒绝。

## 3. 关键字

`let` `mut` `if` `else` `for` `in` `into` `fn` `return` `emit` `break` `continue` `and` `or` `not` `true` `false` `null`

保留但 MVP 不实现：`par` [provisional: P-007]。

规则：

- 关键字永远是关键字，不能作工具名、变量名、函数名、字段名或参数名。
- 内核注册工具时若名字是关键字 → 注册失败（`E_RESERVED_NAME`），不得等到加载脚本才报。
- `into` 在表达式末尾按上下文关键字处理：它终止 `expr`，由 `into_stmt` 消费（见 [02 §3](02-grammar.md)）。

## 4. 数字

- 只接受十进制非负：`0`、`42`、`3.14`；不接受 `1.`、`.5`、`1e9`、十六进制、下划线分隔。
- `1.2.3` 词法为 `1.2` `.` `3`，由文法在字段访问处报错。
- 数字后紧跟标识符字符（如 `12abc`）→ `E_SYNTAX`，不得切成 `12` + `abc`。
- 语义为 IEEE-754 双精度；绝对值不超过 2^53 的整数按整数比较与格式化（见 [03 §1](03-semantics.md)）。

## 5. 运算符与符号

- `-` 只作一元取负或二元减法；**不存在负数字面量**。`read -1` 解析为 `(read) - 1`，加载期报“工具名不能作值”并提示 `read (-1)` [D-003]。
- `|>` 管道；`|?` 降级。两者都要求右侧是一个调用（`|?` 左侧见 [04](04-pipeline-errors.md)）。
- `=` 只用于 `let` 与赋值语句；没有 `+=`、`++`、`??=`。
- `!` 只出现在 `!=`；没有一元 `!`，取反用 `not`。

## 6. 注释

- `#` 到行尾为注释；**注释只吃字符，不吃换行**——`\n` 仍然产出 `NEWLINE` [D-004]。
- 文件开头的 header 行不是注释：在“header 模式”下，`#` 后紧跟 `allow`/`deny`/`emit`/`dsl-version` 与 `:` 的行按 header 解析（见 [02 §2](02-grammar.md)）。header 模式在遇到第一条非 header、非空行、非注释行时结束。
- 除 header 行外，任何 `#` 都开始注释；不支持块注释。

## 7. NEWLINE 生成与抑制

`NEWLINE` 是语句终止符 [D-004]。生成规则：每个 `\n` 产出一个 `NEWLINE`；随后按下列规则**删除**相邻的冗余 `NEWLINE`：

| 规则 | 条件 | 处理 |
| --- | --- | --- |
| N1 | 语句以 `NEWLINE`、`}` 或 `EOF` 终止 | 三者等价；`}`/`EOF` 不产生 token，只结束语句 |
| N2 | 位于 `(` 或 `[` 内部（深度 > 0） | 删除该 `NEWLINE` |
| N3 | 位于 `{` 内部 | **不删除**（emit payload 的 JSON 字面量除外，见 N8） |
| N4 | `NEWLINE` 紧跟在 `\|>` 或 `\|?` 之后 | 删除 |
| N5 | `NEWLINE` 之后的下一个非空 token 是行首 `\|>` 或 `\|?` | 删除该 `NEWLINE` |
| N6 | `NEWLINE` 位于 `}` 与 `else` 之间 | 删除 |
| N7 | 控制头（`if`/`for`/`into`/`fn`/`else`）之后，若下一个非空 token 是 `{` | 删除其间的 `NEWLINE` |
| N8 | emit payload 的 JSON 字面量内部，或 `emit STRING` 与其 payload 之间 | 删除 [D-006] |

补充规则：

- 连续多个 `NEWLINE` 折叠为一个；空行不产生空语句。
- 一行只能有一条语句；`let a = 1 let b = 2` 是语法错误，不是两条语句。
- 实参不跨逻辑行；跨行只能落在 N2/N4/N5 允许的位置。
- 表驱动实现建议：先按括号深度打抑制标记，再做 N4–N8 的相邻 token 修正；修正只看前一个有效 token 与后一个非空 token，不做回溯。

## 8. 与实现语言的关系

CT 现有 lexer 把 `\n` 直接当空白吞掉（`Lexer.h.ct:70`，ct-lang HEAD `6c21f26`），**不能**直接复用；DSL 必须有独立的 token 流与 NEWLINE 抑制层。CT 的 6 类 token（EOF/ID/NUM/STR/PUNCT/PP）也不足以表达 NEWLINE 与 header。
