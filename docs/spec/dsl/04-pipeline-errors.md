# 04 管道与错误

> 规范版本 `v0.1 rev.1`；状态 `unverified`。本卷对应旧文 §4 R1/R2/R4，依据 D-007 与 D-010。

## 1. R1 隐式 await 与 R2 管道传参

- R1：工具调用在 DSL 语义上是同步的；调用点等待结果。DSL 没有 `await`，也没有并行语法。
- R2：`left |> right` 求值 `left`，把该值**追加到 `right` 调用的显式实参之后**：

```
a |> f b        =  f(b, a)
a |> f b |> g   =  g(f(b, a))          # 左结合
x |> grep "pat" =  grep("pat", x)      # grep arity=2；左侧值补到第 2 位
```

- 管道只负责追加实参，不改变工具 arity。个数（显式实参 + 管道值 + `$` 注入）由 `params_schema` 长度与注入规则静态可算，因此在**加载期**与 `fn` 共用同一 `arity` 错误（[07 §3.1](07-runtime.md)）。例如 `read` arity=1，`x |> read "p"` 会得到 2 个实参，加载期报 `arity`，脚本不会执行到该调用。
- **改判说明**：本条此前写“工具不适用 `E_ARITY`，运行时按个数不符报 `constraint`”。该判断是错的——个数不是运行时值，而是 `params_schema` 的静态属性；把它放进第三层意味着脚本要先跑前缀语句、产生副作用，才在调用点失败。现改为加载期 `arity`，与 `unknown_tool`/`tool_not_allowed` 同层。
- `|>` 的右操作数必须是**可调用节点**：一个 `call`、加载期解析为零参调用的裸 `IDENT`（零参工具或零参 `fn`），或首操作数是 `call` 的 `fallback_expr`（如 `a |> (f b |? g c)`，允许分组）。管道值追加到该 `fallback` 链**最左侧**的那个 `call`；`|?` 右侧不接收管道值。其他形式 → 加载期 `E_PIPE_RHS`，提示“管道右侧必须是调用”。
- `|>` 右侧是 `fn` 时，管道值按普通追加实参处理，`fn` 的形参个数必须匹配，否则加载期 `E_ARITY`。
- 管道值参与 §3 的 `$` 注入计数（`n` 含管道值）。

## 2. `|?` 降级

文法（与 [02 §3](02-grammar.md) 一致）：

```
fallback_expr := or_expr ("|?" or_expr)*        # 左结合，高于 |>
```

规则：

1. **优先级**：`|?` 高于 `|>`。`a |> f b |? g c` = `a |> (f b |? g c)` [D-007]。
2. **失败单元**：左侧必须是单个可调用节点（`call`，或解析为零参调用的裸 `IDENT`，可分组），由加载期检查。链式 `|?` 时检查只作用在**链的最左操作数**：`a |? b |? c` = `(a |? b) |? c`，只检查 `a`，不逐段检查 `b`。最左不是可调用节点 → `E_FALLBACK_LHS`，提示用 `fn` 包裹。
3. 失败单元包含该 call 的整次求值：实参求值失败、约束拒绝、handler 失败都算；更早的管道阶段失败不算（见 [04 §3](04-pipeline-errors.md) 表）。
4. 左侧成功 → 右侧**不执行**；左侧失败且错误可捕获 → 执行右侧，结果取右侧值，并置 `degraded=1`。
5. 右侧独立求值：不接收左侧管道值，不继承左侧部分结果；右侧内部嵌套调用的失败由右侧自己的 `|?` 处理。
6. 右侧失败 → 错误继续向外传播，诊断同时给出两侧调用位置。
7. `|?` 只产生值，不产生“错误值”；脚本无法读取错误对象。
8. 同一个表达式链中多个 `|?` 左结合：`a |? b |? c` = `(a |? b) |? c`，任一右侧被采用都置 `degraded=1`。

### 2.1 可捕获与不可捕获

| 类别 | `error_kind` | `|?` 是否捕获 |
| --- | --- | --- |
| 结果不存在 | `not_found` | 捕获 |
| 输入不合法 | `invalid_input` | 捕获 |
| 瞬时失败（可重试） | `transient` | 捕获 |
| 策略拒绝或 OS 权限拒绝 | `denied` | **不捕获** |
| 参数值不满足约束（路径/命令/域名/类型/大小） | `constraint` | **不捕获** |
| 审批 | `approval_required` / `approval_denied` | **不捕获** |
| 资源上限，或输入被上游截断 | `limit` | **不捕获** |
| 策略撤销/脚本变更 | `revoked` / `script_changed` | **不捕获** |
| 内核内部错误 | `internal` | **不捕获** |
| 加载期错误 | 见 [07 §3.1](07-runtime.md)（含 `dollar_outside` 等） | **不捕获**（加载阶段根本不执行） |

- `null` 是值，不是失败：缺键、越界返回 `null`，不触发 `|?`。
- `denied` 同时覆盖**策略拒绝**（调用点授权检查判定不放行）与 **OS 权限拒绝**（如 `EACCES`/`EPERM`）。两者对脚本的可观察后果相同：调用未发生、错误不可恢复、不得被降级改写；拆成两个 kind 只会把宿主文件系统细节泄漏进脚本，且会让“不可捕获”集合随平台变化，因此不新增 kind。
- `constraint` 只覆盖**值层**，判定者是运行时第三层（`ParamConstraint` 与固定 schema 的类型浅校验：路径、命令、域名、大小、固定位的 `string` 类型）。它说明“脚本传的值不对”，不得被静默兜底。**个数不属于这里**：固定 arity 的个数与 `json_build` 的“键值成对”都是静态可算，加载期已报 `arity`。
- `invalid_input` 覆盖**完整**输入的内容不合法，判定者是 handler：编码、JSON 语法、正则、`json_build` 的键不是 `string`、重复键。
- `limit` 除 `ExecLimits` 超限外，还覆盖 `requires_complete_input=1` 的工具收到被上游截断的实参（[07 §1/§3.2](07-runtime.md)）。后者由运行时在 handler 之前判定；半截输入不是“内容不合法”，不得降为可捕获的 `invalid_input`。
- 工具用 `error_kind` 表达失败；返回 `null` 不等价于失败。
- 不可捕获错误即使出现在 `|?` 左侧，也按 §3 中止块；这是安全要求：`denied`/`limit` 不得被静默改写为正常结果。

## 3. R4 失败行为表

R4 的完整表述 [D-010]：

> 运行时失败是附着在产生它的那次 call 上的控制信号，不是值；它中止最近的块并向外传播。唯一消费者是 `|?`，且只消费它左侧那个 call 的信号。MVP 只有调用级降级，**没有块级恢复**。

| 场景 | 行为 | 结果 |
| --- | --- | --- |
| 普通工具/`fn` 调用失败（任何类别） | 中止当前块，信号向外 | `ok=0`，`error_kind` 原样上抛 |
| `|?` 左侧失败，类别可捕获 | 不中止，执行右侧 | `ok=1`，`degraded=1`，值为右侧结果 |
| `|?` 左侧失败，类别不可捕获 | 中止当前块 | `ok=0`，`error_kind` 上抛 |
| `|?` 右侧失败 | 中止当前块，诊断含两侧位置 | `ok=0` |
| `if` 条件求值失败 | 中止包含该 `if` 的块 | `ok=0` |
| `for` 的集合求值失败 / 非数组 | 中止，`E_FOR_NOT_ARRAY` 或上抛 | `ok=0` |
| 循环体内失败 | 中止 `for` 块，不继续下一轮 | `ok=0` |
| `emit` 无订阅方或队列满 | 丢弃并记日志，不中止 | `ok` 不变 |
| `emit` 超出 `max_emit_bytes`/`max_payload_depth` | 中止当前块 | `ok=0`，`error_kind=limit` |
| `emit` payload 不符合内核 schema | 中止当前块 | `ok=0`，`error_kind=emit_schema` |
| 步数/调用数/超时/深度超限 | 中止整个执行 | `ok=0`，`error_kind=limit` |
| 策略在调用边界被撤销 | 中止 | `ok=0`，`error_kind=revoked` |
| `|?` 已发生的副作用 | **不回滚** | 需工具提供补偿 |

- `fn` 体内失败中止 `fn` 体，该 `fn` 调用失败；调用方的 `|?` 可消费它。
- 没有 `try/catch`、没有错误值、没有恢复执行；一个失败要么中止块，要么被恰好一个 `|?` 变成值。
- 块中止时，块内此前完成的工具副作用保留。

## 4. 可观测字段

`DslResult`（完整定义见 [07 §1](07-runtime.md)）必须回显：

| 字段 | 含义 |
| --- | --- |
| `ok` | 1 成功，0 失败 |
| `error_kind` | 失败类别；成功时为 `null` |
| `degraded` | 1 表示本次执行至少使用过一次 `|?` 右侧；否则 0 |
| `value_json` | 最后一条 `expr_stmt` 的值；`ok=0` 时为 `null` |
| `error_line` / `error_col` | 失败位置（1 基） |
| `policy_generation` | 本次执行使用的策略代（[06 §3](06-security.md)） |

`degraded` 的存在理由：没有它，调用方无法区分“全部正常”与“全部走兜底”，而两者在 agent 任务里含义完全不同。
