# 规格层（Spec）

> 本目录只放带稳定 ID 的对外行为条目。状态词严格区分：
>
> - `accepted`：已拍板且已验收；当前 **0 条**。
> - `unverified`：已拍板、但尚无实现或无门禁证据；当前 [S-001](S-001-call-form.md)。
> - `pending`：未拍板，验收判据未定；见 [PENDING](PENDING.md)。不得当作已生效规则引用。

## 1. 条目索引

| ID | 行为 | 状态 | 决策 | 文件 |
| --- | --- | --- | --- | --- |
| S-001 | 调用统一空格形态；括号只作分组与 `fn` 参数表 | unverified | D-001 | [S-001](S-001-call-form.md) |
| P-001..P-019 | 未决问题（文法、语义、安全、边界） | pending | 无 | [PENDING](PENDING.md) |

## 2. 条目格式

每个 `S-*` 条目必须具备：

1. 状态与决策锚点；
2. 输入（可解析的源码形态）；
3. 输出（AST/运行结果的可观察约定）；
4. 失败语义（错误类别、位置、是否拒绝加载）；
5. 验收命令与阈值（没有就写 `尚未落盘`，不得写“通过”）；
6. 证据锚点（提交 sha、`file:line`）。

## 3. 验收命令约定

- 当前仓库没有构建、没有门禁、没有 `docs/acceptance.md`；所有验收命令均为 `尚未落盘`。
- M1 落地后才补：`tools/check.sh g1`（文档/规格完整性）、golden 解析用例、`tools/check-docs.sh`（锚点与 snippet）。
- 在命令存在之前，本目录任何条目都不得标 `accepted`。

## 4. 与主张层的关系

- 主张层：`docs/requirements/README.md`（目标、非目标、约束、术语、决策索引）。
- 规格层只回答“做什么、怎么判对错”，不重复目标与理由。
- 未决项只在 `PENDING.md` 出现；不允许在 `S-*` 条目里把待定细节写成已生效规则。
