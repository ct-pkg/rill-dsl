## 8. 理由（逐条对应判据）

**B2-1（`|?` 优先级）**：J2 是决定性判据。按讨论稿 P0-11 的“低于 `|>`”（L 方案），`read "primary" |? read "fallback" |> parse` 解析为 `read "primary" |? (read "fallback" |> parse)`：primary 成功时 `parse` **根本不执行**，脚本把未解析的原始字符串当配置继续用，且不报错。`read "a" |> f |? g |> h` 同理会在成功路径跳过 `h`。这不是风格差异，是语法决定的求值轨迹，可由文法直接推出（主张席 S2/S3）。因此用户此前的口头裁定“低于”以证据改判为“高于”。反方最强论点是“整条链兜底更符合直觉”；不成立：整条链兜底可用 `fn load() { ... }` + `load |? fallback` 表达（fn 边界即恢复粒度），不需要把 `|?` 放低。反证席与主张席在“左操作数单个 call”上独立收敛，且反证席要求“静态确定”，故辅以加载期 FB-L1 检查，把失败单元从“运行期最后执行”改成“源码上那个 call”。

J3 采纳反证席：`|?` 若捕获 `denied`/`limit`，一次越权尝试会被静默改写为合法读取并让脚本成功退出，审计上看不到越权（B3 反证席 §1.3 同向）。工具失败必须是枚举，`null`（如缺键）是值不是失败，这同时消除反证席 §1.2 的分叉。

J4 采纳主张席的“按形参位注入”：R2 说管道值追加末尾、R3 说 `$` 追加末尾，两句同时成立就没有“末尾”。规则定为“显式参数 → 管道值 → 隐式 `$`；仅当显式+管道参数个数 n < 固定位置形参 m 且工具声明 `accepts_context` 时注入；变长/未知 schema 不注入，要求显式 `$`”。反证席的“`$` 永远最后注入”保留为顺序，但缺少“是否注入”的判据，会制造 3 参调用 2 参 schema 的错位。

**B2-2（截断暴露）**：这是本组唯一“伪字段 vs 信封”的正面对撞。选 C 的依据不是成本，而是两条硬约束：其一，用户更正已定“DSL 层只规定通用结果元数据 `{ value, truncated, original_size }`，字段访问必须能读到 `truncated`”——E 方案把元数据完全交给工具 payload，DSL 不再规定任何元数据形状，等于撤回用户更正；其二，J5 要求“工具只见 payload”，A/B 都让记录进入工具边界或迫使解释器自动拆包（第四条隐式规则），违反 §1 原则 3。C 的侧车对工具边界零影响，J6 对所有值恒真（静态可判），J8 示例零改动。反证席最强的两点逐条回应：（a）“JSON 自带 `truncated` 冲突”——R-M3 伪字段优先是确定规则，R-M4 用普通工具调用 `get "truncated" x` 逃逸，不新增语法，J7 成立；（b）“C 需要专用操作符就失去 token 优势”——逃逸不需要操作符，`get` 已是工具。B 方案被否的理由是反证席 §2.3 自己给出的：记录经 `fn` 返回/管道后形态依赖 callee，LLM 无法预测。D 被两席共同否掉（形状随数据变，golden 不可写）。J9 采纳主张席的粘性规则：`truncated = 本次截断 || 任一输入 truncated`，否则 `read 截断 -> grep` 会把截断洗白成“没搜到”，这是可证明的假阴性。粘性超出用户原意的风险记入失效条件。

**B2-3（循环与赋值）**：J10 上，反证席 §3.1 给出了不加赋值时最硬的失败：LLM 用 `let report = report + chunk` 遮蔽累加，脚本退出 0 却写出空文件。两席都要求赋值，故赋值 upheld。分歧在 `let mut`：反证席主张任意既有绑定可赋值、`let` 同名重声明报错；主张席主张仅 `let mut` 可赋值。选主张席，理由是反证席的方案让所有绑定默认可变，`let` 的“此后不变”阅读保证消失，而漏写 `mut` 的失败是加载期、带 hint、一次可改（J13）；`let mut` 对现有五个示例零 token 成本。J12 采纳“`for` 变量每轮不可变值拷贝”，与项目已裁的 item 值拷贝硬约束一致，也消除了反证席 §3.2 的遮蔽累加。`break`/`continue`：两席对 `break`（仅 `for`）无实质分歧；`continue` 上反证席以“跳过自增导致死循环”反对，但该风险只存在于 `while`，而 `while` 已被两席共同排除，`for x in xs` 没有自增可跳，故 `continue` upheld（且它是“跳过坏项”的唯一手段，反证席 §1.5 指出的迭代级恢复缺口只能靠它缓解）。`while` rejected：两席一致不进 MVP，J11 的终止性论证成立（空体 `while true` 只能靠 `max_steps` 粗粒度兜底，且 LLM 会重写同一循环）；重开条件写入 D-009。

**B2-4（R4）**：J14 上，现行 R4 的“if/for/into/fn 块内失败，整个块中止”在含 `|?` 的块里为假，“MVP 不做 try/catch”在已有调用级捕获后也是错话。反证席“不字面矛盾但已成一句错话”的定性准确，成本席“这是硬矛盾，必须改一句”同向。采纳主张席 R4.0–R4.6 的结构，并补反证席三项：失败行为表（普通调用 / `|?` 左操作数 / emit）、`DslResult.degraded`（否则内核无法区分“全部正常”与“全部兜底”）、显式声明“`|?` 不回滚已发生的副作用、MVP 无块级恢复”。把“MVP 不做 try/catch”改为“MVP 只有调用级降级，没有块级恢复”，是 J15 的关键：把缺口语义写明，而不是用否认掩盖。

| 争点 | 触发条件 | 处置 |
